Why the standard library matters

In many languages the first thing you do on a new project is install a pile of packages: one for HTTP, one for JSON, one for logging, one for command-line flags. In Go, the standard library (often called the stdlib) already covers most of that, and it is maintained by the Go team with the same compatibility promise as the language itself. Code written against it in 2014 still compiles today.

That has real consequences at work:

  • Fewer dependencies means fewer security advisories, fewer breaking upgrades, and faster builds.
  • Shared vocabulary. Every Go developer knows io.Reader, http.Handler and context.Context. Libraries plug into these, so they plug into each other.
  • High-quality reference code. The stdlib source is very readable. When you wonder "how should I design this?", reading how bufio or encoding/csv does it is a great education.
Senior engineer tip

Before adding a dependency, ask "does the stdlib already do 90% of this?" It usually does. A tiny helper function you own is often cheaper over five years than a library you don't. Reach for third-party packages when they bring real value (a database driver, a mature router with features you actually need), not for convenience wrappers.

We'll go roughly from the lowest-level building blocks (bytes flowing through readers and writers) up to higher-level packages (JSON, time, logging), and finish with a complete tool.

io.Reader and io.Writer: Go's universal plugs

Almost every piece of data in Go flows through two tiny interfaces:

type Reader interface {
	Read(p []byte) (n int, err error)
}

type Writer interface {
	Write(p []byte) (n int, err error)
}

A Reader is anything you can pull bytes out of: a file, a network connection, an HTTP request body, a string in memory, a gzip stream. A Writer is anything you can push bytes into: a file, stdout, a hash, a network connection, a buffer.

The contract of Read is worth learning precisely, because you'll implement it one day:

  • The caller hands you a buffer p. You fill up to len(p) bytes and return how many you filled, n.
  • You may return fewer bytes than asked for. That's normal, not an error.
  • When there is no more data, you return io.EOF ("end of file"). You may return the last bytes and io.EOF in the same call, so callers must process the n bytes before looking at err.
Mental model

Think of Readers and Writers as garden hoses with standard connectors. Because every hose uses the same fitting, you can connect a tap (a file) to a filter (gzip) to a splitter (MultiWriter) to a sprinkler (a network socket). None of them needs to know what's on the other end.

Here is that exact pipeline as a program. Four helpers from the io package do all the work:

  • io.LimitReader(r, n) stops after n bytes. Great for protecting yourself from huge inputs.
  • io.TeeReader(r, w) returns a Reader that, as you read from it, also writes the same bytes into w (like the Unix tee command).
  • io.MultiWriter(w1, w2, ...) duplicates every write to all of its writers.
  • io.Copy(dst, src) reads from src and writes to dst until EOF, using a 32 KB buffer internally. It returns the byte count.
package main

import (
	"bytes"
	"fmt"
	"io"
	"os"
	"strings"
)

func main() {
	src := strings.NewReader("Hello, Gopher! This is a long message.")

	// 1. LimitReader: only let the first 14 bytes through.
	limited := io.LimitReader(src, 14)

	// 2. TeeReader: everything read from `limited` is also copied into `audit`.
	var audit bytes.Buffer
	tee := io.TeeReader(limited, &audit)

	// 3. MultiWriter: one write goes to stdout AND to `saved`.
	var saved bytes.Buffer
	out := io.MultiWriter(os.Stdout, &saved)

	// 4. io.Copy pumps data from a Reader into a Writer until EOF.
	n, err := io.Copy(out, tee)
	fmt.Println()
	fmt.Println("copied:", n, "err:", err)
	fmt.Printf("audit: %q\n", audit.String())
	fmt.Printf("saved: %q\n", saved.String())

	// What is left in the original reader?
	rest, _ := io.ReadAll(src)
	fmt.Printf("rest:  %q\n", rest)
}

  1. We wrap a plain string in a strings.Reader. Nothing has been read yet; it just remembers a position (0).
  2. The LimitReader wraps src and keeps a counter N=14. Each read decreases it; at 0 it reports io.EOF.
  3. The TeeReader wraps limited. Still nothing has moved. Building pipelines is lazy: no data flows until someone reads.
  4. On the writing side, MultiWriter will send every write to both stdout and saved.
  5. Now io.Copy calls tee.Read repeatedly. Each read goes tee → limited → src, the bytes get copied into audit, and then written to both stdout and saved. After 14 bytes the limit hits 0, the next read returns EOF, and Copy stops. EOF is the normal end, so err is nil.
  6. We finish the line and print the count.
  7. The original reader still holds the bytes that the limit kept out. Readers are stateful streams: what's been read is gone, the rest is still there.

Writing your own Reader and Writer

Because the interfaces are tiny, writing your own is easy. Below, upperReader wraps another Reader and upper-cases letters as they pass, and countingWriter counts bytes on their way to stdout. Notice that io.Copy has no idea either of these types exists. It just sees a Reader and a Writer.

package main

import (
	"fmt"
	"io"
	"os"
	"strings"
)

// upperReader wraps another Reader and upper-cases ASCII letters.
type upperReader struct {
	r io.Reader
}

func (u upperReader) Read(p []byte) (int, error) {
	n, err := u.r.Read(p) // read into the caller's buffer first
	for i := 0; i < n; i++ {
		if 'a' <= p[i] && p[i] <= 'z' {
			p[i] -= 'a' - 'A'
		}
	}
	return n, err // pass through n and err exactly
}

// countingWriter counts bytes that pass through it.
type countingWriter struct {
	w     io.Writer
	total int
}

func (c *countingWriter) Write(p []byte) (int, error) {
	n, err := c.w.Write(p)
	c.total += n
	return n, err
}

func main() {
	cw := &countingWriter{w: os.Stdout}
	r := upperReader{strings.NewReader("readers compose like lego\n")}
	if _, err := io.Copy(cw, r); err != nil {
		fmt.Println("error:", err)
	}
	fmt.Println("bytes written:", cw.total)
}
  1. We build the destination: a *countingWriter that forwards to stdout. It must be a pointer, because Write has a pointer receiver and mutates total.
  2. The source is an upperReader wrapping a 26-byte strings.Reader. Building it reads nothing.
  3. Inside io.Copy, the only things it knows are "something with Read" and "something with Write". It allocates a 32 KB buffer p and calls r.Read(p).
  4. Dynamic dispatch lands in our upperReader.Read. It first lets the inner reader fill p: all 26 bytes arrive in one go, with err=nil.
  5. We rewrite only p[:n], in place. Each lowercase letter drops by 32 ('a'-'A'). Spaces and \n are left alone. Bytes past n are garbage and must not be touched.
  6. We return 26, nil unchanged. Back in io.Copy, because n > 0 it now calls cw.Write(p[:26]).
  7. countingWriter.Write forwards to stdout, so the line appears, and adds the 26 bytes written to total.
  8. Copy loops and calls Read again. The inner reader is empty, so it returns 0, io.EOF, and we pass that through. The uppercase loop runs zero times.
  9. Copy treats io.EOF as a normal end, not a failure, and returns err == nil. The error branch is skipped.
  10. We print the counter. 25 letters and spaces plus 1 newline makes 26.

Gotcha: only touch p[:n]

A Reader can return n < len(p). Everything after p[n] is garbage from a previous read. Always loop to n, never to len(p). And when you see both data and an error, handle the data first. The io.ReadFull, io.ReadAll and io.Copy helpers already get this right, so prefer them over calling Read yourself.

bufio: buffering and line-by-line reading

Every call to Read or Write on a file or socket is a system call, which means asking the operating system kernel to do something. System calls are slow compared to normal function calls. If you write a file one byte at a time, you make a million system calls for a megabyte. The bufio package fixes this by keeping a buffer (4096 bytes by default) in memory and talking to the OS in big chunks.

bufio.Scanner: the right way to read lines

A Scanner splits a stream into tokens. By default a token is a line (without the trailing newline). You can swap the split function to get words (bufio.ScanWords), runes or bytes.

package main

import (
	"bufio"
	"fmt"
	"os"
	"strings"
)

const text = `first line
second line

fourth line after a blank one`

func main() {
	// Line by line.
	sc := bufio.NewScanner(strings.NewReader(text))
	lineNo := 0
	for sc.Scan() {
		lineNo++
		fmt.Printf("%d: %q\n", lineNo, sc.Text())
	}
	if err := sc.Err(); err != nil { // always check after the loop
		fmt.Println("scan error:", err)
	}

	// Word by word: just swap the split function.
	ws := bufio.NewScanner(strings.NewReader(text))
	ws.Split(bufio.ScanWords)
	words := 0
	for ws.Scan() {
		words++
	}
	fmt.Println("words:", words)

	// Buffered writing: bytes sit in memory until Flush.
	w := bufio.NewWriter(os.Stdout)
	defer w.Flush() // without this, nothing below is printed!
	for i := range 3 {
		fmt.Fprintf(w, "buffered row %d\n", i)
	}
	fmt.Fprintf(w, "buffered so far: %d bytes, available: %d\n", w.Buffered(), w.Available())
}
  1. A line Scanner wraps the text. Nothing is read yet.
  2. First Scan() finds the first \n. The token excludes the newline.
  3. Second line, same thing.
  4. The blank line gives an empty token. It is still a line, so the loop continues instead of stopping.
  5. The last line has no trailing \n, and Scanner still returns it at EOF.
  6. Scan() returns false. Err() is nil because a clean EOF is not an error, so nothing prints.
  7. A new Scanner with ScanWords splits on any whitespace, including newlines, and drops the empty line: 2 + 2 + 6 = 10 words.
  8. We wrap stdout in a bufio.Writer (4096-byte buffer). defer w.Flush() is registered now but runs only when main returns.
  9. Three Fprintf calls land in memory, not on the terminal. Each row is 15 bytes, so 45 bytes are buffered. Nothing has been printed yet.
  10. The arguments are evaluated before this line's own bytes are added: 45 buffered and 4096 − 45 = 4051 free. The line itself goes into the buffer too.
  11. main returns, and the deferred Flush fires. All four lines reach stdout in a single write. Without the defer they would be lost.

  3. sc.Text() gives us a string copy of the token.

  6. Now Scan() returns false: either EOF or an error. The loop ends.

Gotcha: the 64 KB line limit

By default a Scanner refuses tokens larger than 64 KB and stops with bufio.Scanner: token too long. Minified JSON logs hit this all the time. Raise the limit with sc.Buffer:

package main

import (
	"bufio"
	"fmt"
	"strings"
)

func main() {
	long := strings.Repeat("x", 100_000) // one 100 KB line
	sc := bufio.NewScanner(strings.NewReader(long))
	for sc.Scan() {
	}
	fmt.Println("default:", sc.Err())

	sc = bufio.NewScanner(strings.NewReader(long))
	sc.Buffer(make([]byte, 0, 64*1024), 1024*1024) // allow lines up to 1 MB
	for sc.Scan() {
		fmt.Println("line length:", len(sc.Text()))
	}
	fmt.Println("bigger buffer:", sc.Err())
}
  1. One line of 100,000 xs with no newline, wrapped in a default Scanner (max token 64 KB).
  2. The Scanner grows its buffer while looking for a newline. When the buffer reaches 64 KB with no token found, it gives up. The very first Scan() returns false and the loop body never runs.
  3. This is why you check Err(). Without it the loop looks exactly like an empty file, and the data silently disappears.
  4. A fresh Scanner, and Buffer gives it a 64 KB starting buffer that may grow up to 1 MB. Call it before the first Scan, or it panics.
  5. Now the buffer can grow past 100 KB, so the whole line comes back as one token at EOF.
  6. The next Scan() hits clean EOF, so Err() is nil.

Also: sc.Bytes() returns a slice that points into the Scanner's internal buffer, and it gets overwritten by the next Scan(). If you need to keep it, copy it (or use sc.Text(), which copies into a new string).

bufio.Writer: remember to Flush

A bufio.Writer collects writes in memory and only sends them to the underlying writer when the buffer is full or when you call Flush(). If your program ends without flushing, the tail of your output simply vanishes. Here's the bug in its smallest form:

package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	w := bufio.NewWriter(os.Stdout)
	fmt.Fprintln(w, "will I be printed?")
	fmt.Println("direct write: buffered bytes =", w.Buffered())
	// forgot w.Flush()
}

import (
	"errors"
	"fmt"
	"io/fs"
	"os"
	"path/filepath"
)

func main() {
	dir, err := os.MkdirTemp("", "files-demo")
	if err != nil {
		panic(err)
	}
	defer os.RemoveAll(dir) // clean up the whole temp dir at the end

	path := filepath.Join(dir, "notes.txt")

	// 1. Create (truncates if it exists) and write.
	f, err := os.Create(path)
	if err != nil {
		panic(err)
	}
	fmt.Fprintln(f, "line one")
	if err := f.Close(); err != nil { // Close can fail on write: check it!
		panic(err)
	}

	// 2. Append with OpenFile and explicit flags.
	f, err = os.OpenFile(path, os.O_APPEND|os.O_WRONLY, 0)
	if err != nil {
		panic(err)
	}
	f.WriteString("line two\n")
	f.Close()

	// 3. Read the whole thing in one go.
	data, err := os.ReadFile(path)
	if err != nil {
		panic(err)
	}
	fmt.Printf("contents:\n%s", data)

	// 4. Write a whole file in one go, with permissions 0644 (rw-r--r--).
	cfg := filepath.Join(dir, "config.ini")
	if err := os.WriteFile(cfg, []byte("debug=true\n"), 0o644); err != nil {
		panic(err)
	}
	info, _ := os.Stat(cfg)

	_, err = os.ReadFile(filepath.Join(dir, "missing.txt"))
	fmt.Println("missing is ErrNotExist:", errors.Is(err, fs.ErrNotExist))

A few things to notice:

  • Permissions are Unix-style octal numbers. 0o644 means the owner can read and write (6 = 4+2), the group and others can only read (4). Directories usually want 0o755 (the 1 bit, "execute", lets people enter a directory). Your process's umask may remove bits from what you ask for.
  • Errors are typed. A missing file returns a *fs.PathError that wraps fs.ErrNotExist. Check it with errors.Is(err, fs.ErrNotExist) (or the older os.IsNotExist).
  • Close can fail. For files you wrote to, the OS may only report a disk-full error on close. defer f.Close() is fine for files you only read.
Senior engineer tip: atomic writes

If a crash happens halfway through os.WriteFile("config.json", ...), you're left with a half-written config. For important files, write to a temp file in the same directory (os.CreateTemp(dir, "config-*.tmp")), Sync() and Close() it, then os.Rename it over the real name. Rename is atomic on the same file system, so readers see either the old file or the new one, never a mix.

Environment variables, arguments and exit codes

os.Args is a slice of the command-line words; os.Args[0] is the program's own path. os.Getenv reads an environment variable, returning "" if it isn't set. When you need to tell "unset" apart from "set to empty", use os.LookupEnv. os.Exit(code) ends the process immediately with a status code: 0 means success, anything else means failure (2 is the convention for "bad usage").

package main

import (
	"fmt"
	"os"
)

func main() {
	defer fmt.Println("deferred: runs only on a normal return")

	fmt.Println("program:", os.Args[0] != "")
	fmt.Println("args:", os.Args[1:])

	port := os.Getenv("PORT") // "" if unset: can't tell unset from empty
	fmt.Printf("PORT=%q\n", port)

	if v, ok := os.LookupEnv("APP_MODE"); ok {
		fmt.Println("APP_MODE is set to", v)
	} else {
		fmt.Println("APP_MODE is not set")
	}

	if len(os.Args) < 2 {
		fmt.Fprintln(os.Stderr, "usage: env NAME")
		os.Exit(2) // exits immediately; deferred calls do not run
	}
}
  1. We trace the second run: PORT=8080 APP_MODE=dev ./env alice bob. The defer is registered first; it will run when main returns normally.
  2. os.Args[0] is the program path, never empty, so this prints true.
  3. The real arguments start at index 1. The shell already split them on spaces.
  4. Getenv returns the value. On run 1 it returned "", and you could not tell "unset" from "set to empty".
  5. LookupEnv also returns ok, which tells those two cases apart.
  6. 3 is not less than 2, so we skip the usage branch. On run 1 (no args) this is where os.Exit(2) killed the process without running the defer.
  7. main reaches its closing brace and returns normally, so the deferred Println fires last. The exit status is 0.

Gotcha: os.Exit skips defers

os.Exit does not run deferred functions. Files don't get flushed, temp dirs don't get removed, buffered logs are lost. That's why the first run above never printed the deferred line. The fix is a pattern you'll see in the CLI at the end: put all logic in a run() error function, and only call os.Exit in main after run has returned and its defers have finished.

path/filepath: portable paths and walking trees

Paths on Linux and macOS use /; Windows uses \. Never glue paths with + "/" +. The path/filepath package uses the right separator for the current OS and also cleans up things like .. and double slashes. (The separate path package is for forward-slash paths that are not OS file paths, like URL paths or paths inside an embed.FS.)

To visit every file under a directory, use filepath.WalkDir. It calls your function for each entry in lexical order. Returning filepath.SkipDir from a directory means "don't go inside"; returning any other error stops the walk.

package main

import (
	"fmt"
	"io/fs"
	"os"
	"path/filepath"
	"strings"
)

func main() {
	p := filepath.Join("data", "2026", "..", "reports", "q3.csv")
	fmt.Println("Join:", p) // Join also cleans ".." away
	fmt.Println("Dir: ", filepath.Dir(p))
	fmt.Println("Base:", filepath.Base(p))
	fmt.Println("Ext: ", filepath.Ext(p))
	fmt.Println("Stem:", strings.TrimSuffix(filepath.Base(p), filepath.Ext(p)))
	rel, _ := filepath.Rel("data", p)
	fmt.Println("Rel: ", rel)

	// Build a small tree to walk.
	root, _ := os.MkdirTemp("", "walk")
	defer os.RemoveAll(root)
	for _, f := range []string{"a.go", "b.txt", "sub/c.go", "sub/deep/d.go", "vendor/x.go"} {
		full := filepath.Join(root, f)
		os.MkdirAll(filepath.Dir(full), 0o755)
		os.WriteFile(full, []byte("package x"), 0o644)
	}

	// WalkDir visits every entry in lexical order.
	err := filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err // could not read this entry
		}
		if d.IsDir() && d.Name() == "vendor" {
			return filepath.SkipDir // do not descend
		}
		if !d.IsDir() && filepath.Ext(path) == ".go" {
			r, _ := filepath.Rel(root, path)
			fmt.Println("found", r)
		}
		return nil
	})
	fmt.Println("walk err:", err)

	matches, _ := filepath.Glob(filepath.Join(root, "*.go"))
	fmt.Println("glob matched:", len(matches))
}
  1. Join glues the parts with the OS separator and then cleans the result: 2026/.. cancels out.
  2. These are pure string operations. Nothing touches the disk. Ext includes the dot, so trimming it from Base gives the stem.
  3. Rel answers "how do I get from data to p?"
  4. We create a temp tree. defer os.RemoveAll(root) cleans it up when main ends.
  5. WalkDir calls our function for root itself first. It's a dir, not vendor, not a file, so we return nil, which means "keep going".
  6. Entries come in lexical order: a.go is first, and it's a .go file, so we print it relative to root.
  7. b.txt fails the extension check. Nothing printed.
  8. We visit the sub directory, then descend into it and find c.go.
  9. Then sub/deep, then sub/deep/d.go. The walk is depth-first.
  10. At vendor we return the special sentinel filepath.SkipDir. WalkDir does not descend, so vendor/x.go is never visited.
  11. SkipDir is a signal, not a failure, so WalkDir returns nil.

encoding/json: the everyday workhorse

JSON is how most services talk. encoding/json converts between Go values and JSON text:

  • json.Marshal(v) turns a Go value into JSON bytes ("encoding").
  • json.Unmarshal(data, &v) parses JSON bytes into a Go value ("decoding"). You must pass a pointer so it can fill your variable.

Only exported fields (starting with a capital letter) are visible to the json package. Struct tags, the back-quoted strings after a field, control the JSON key and options:

TagMeaning
`json:"name"`Use name as the key
`json:"name,omitempty"`Skip if the value is "empty": false, 0, "", nil pointer/interface, empty slice/map
`json:"name,omitzero"`(Go 1.24+) Skip if the value is the zero value, or if its IsZero() method returns true. Works for structs and time.Time
`json:"-"`Never encode or decode this field
`json:"n,string"`Encode a number or bool inside a JSON string ("36")

Streaming with json.Decoder and json.Encoder

json.Unmarshal needs the whole document in memory. json.NewDecoder(r) reads from any io.Reader instead, one value at a time. Use it for HTTP request bodies, newline-delimited JSON (NDJSON) log files, and huge arrays. Its mirror image, json.NewEncoder(w), writes straight to an io.Writer.

package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"os"
	"strings"
)

type Event struct {
	Level string `json:"level"`
	Msg   string `json:"msg"`
}

func main() {
	// 1. NDJSON: one JSON value per line. Decoder reads them one at a time.
	ndjson := `{"level":"info","msg":"started"}
{"level":"warn","msg":"disk 91%"}
{"level":"error","msg":"db timeout"}`
	dec := json.NewDecoder(strings.NewReader(ndjson))
	for {
		var e Event
		err := dec.Decode(&e)
		if errors.Is(err, io.EOF) {
			break
		}
		if err != nil {
			fmt.Println("bad line:", err)
			break
		}
		fmt.Printf("[%s] %s\n", e.Level, e.Msg)
	}

	// 2. A huge JSON array: stream elements without loading them all.
	arr := `[{"level":"info","msg":"a"},{"level":"info","msg":"b"}]`
	dec = json.NewDecoder(strings.NewReader(arr))
	tok, _ := dec.Token() // consume the opening '['
	fmt.Println("opening token:", tok)
	count := 0
	for dec.More() {
		var e Event
		dec.Decode(&e)
		count++
	}
	dec.Token() // consume the closing ']'
	fmt.Println("streamed elements:", count)

	// 3. Strict decoding for API input: reject unknown fields.
	strict := json.NewDecoder(strings.NewReader(`{"level":"info","mesage":"typo"}`))
	strict.DisallowUnknownFields()
	var e Event
	fmt.Println("strict:", strict.Decode(&e))

	// 4. Encoder writes straight to any io.Writer (here: stdout).
	enc := json.NewEncoder(os.Stdout)
	enc.SetIndent("", " ")
	enc.Encode(Event{Level: "debug", Msg: "<html> & stuff"})
}

Custom MarshalJSON and UnmarshalJSON

If a type has a MarshalJSON() ([]byte, error) method, the json package calls it instead of using the default encoding. Likewise for UnmarshalJSON([]byte) error. This is how you make an integer enum appear as a readable word, or a time.Duration appear as "1m30s" instead of 90000000000.

package main

import (
	"encoding/json"
	"fmt"
	"strings"
	"time"
)

// Status is stored as an int but should look like a word in JSON.
type Status int

const (
	Todo Status = iota
	Doing
	Done
)

var statusNames = []string{"todo", "doing", "done"}

func (s Status) MarshalJSON() ([]byte, error) {
	if int(s) >= len(statusNames) {
		return nil, fmt.Errorf("invalid status %d", s)
	}
	return json.Marshal(statusNames[s]) // reuse Marshal to get quoting right
}

func (s *Status) UnmarshalJSON(b []byte) error { // pointer receiver: we modify s
	var name string
	if err := json.Unmarshal(b, &name); err != nil {
		return fmt.Errorf("status must be a string: %w", err)
	}
	for i, n := range statusNames {
		if strings.EqualFold(n, name) {
			*s = Status(i)
			return nil
		}
	}
	return fmt.Errorf("unknown status %q", name)
}

// Duration wraps time.Duration so JSON shows "1m30s" instead of nanoseconds.
type Duration struct{ time.Duration }

func (d Duration) MarshalJSON() ([]byte, error) { return json.Marshal(d.String()) }

func (d *Duration) UnmarshalJSON(b []byte) error {
	var s string
	if err := json.Unmarshal(b, &s); err != nil {
		return err
	}
	v, err := time.ParseDuration(s)
	d.Duration = v
	return err
}

	Title    string   `json:"title"`
	Status   Status   `json:"status"`
	Estimate Duration `json:"estimate"`
}

	fmt.Println("minutes:", back.Estimate.Minutes())

	err = json.Unmarshal([]byte(`{"status":"blocked"}`), &back)
	fmt.Println("error:", err)

CSV looks trivial until a field contains a comma, a quote or a newline. encoding/csv handles all the quoting rules (RFC 4180) so you don't have to. Every field comes back as a string; converting to numbers is up to you with strconv.

  4. The quoted field "Hopper, Grace" comes back as one field with the comma inside and the quotes removed. Splitting on commas by hand would get this wrong.

  7. 91 + 88 + 79.
  8. Both rows go into the writer's buffer. The comment contains a comma and double quotes, so the writer will quote it.
  9. Flush sends the rows out. Inner quotes are doubled (""hi"") and the field is wrapped in quotes. Write errors only show up through w.Error() after Flush.

time: instants, durations, formats and zones

The time package has two core types:

  • time.Time is an instant: a specific moment, plus a location (time zone) used for display.
  • time.Duration is a length of time, stored as an int64 count of nanoseconds. Constants like time.Second and time.Millisecond make it readable: 90 * time.Second.

The monotonic clock

Your computer's wall clock can jump: NTP corrects it, someone changes it, daylight saving shifts it. If you measured elapsed time with wall clock readings, you could get negative durations. So time.Now() records two readings: the wall clock (for telling time) and a monotonic clock that only ever moves forward (for measuring time). time.Since and t.Sub use the monotonic reading when both values have one. You can see it in the printed value as m=+...:

	"fmt"
	"time"

	start := time.Now()
	fmt.Println(start) // note the "m=+0.000..." suffix: the monotonic reading

	time.Sleep(25 * time.Millisecond)
	elapsed := time.Since(start) // uses the monotonic clock: safe from clock jumps
	fmt.Println("elapsed >= 25ms:", elapsed >= 25*time.Millisecond)
	fmt.Println("rounded:", elapsed.Round(time.Millisecond))

	wall := start.Round(0) // Round(0) strips the monotonic reading
	fmt.Println(wall)
}

	msg := fmt.Sprintf("hello, %s%s", *name, sep)
	if *shout {
		msg = strings.ToUpper(msg)
	}
	for i := range *times {
		if i > 0 {
			time.Sleep(*wait)
		}
		fmt.Println(msg)
	}
	fmt.Println("positional args:", flag.Args())
}
  1. We trace greet -name=Gopher -n 2 -shout extra words. Each flag.X call registers a flag and returns a pointer holding the default for now.
  2. StringVar binds the flag to an existing variable instead. It is set to the default right away.
  3. We replace the help printer. It only runs on -h or a parse error.
  4. Parse walks os.Args[1:], writes through the pointers, and stops at the first non-flag (extra). Everything after that is positional. A bool flag takes no separate value.
  5. We dereference to read the values: "hello, Gopher!", then *shout upper-cases it. Reading before Parse would have given the defaults.
  6. range *times counts 0 and 1. On the first pass there is no sleep.
  7. Second pass: sleep for *wait (0 here, so instant), then print again.
  8. flag.Args() returns what Parse left over.

log/slog: structured logging

Classic logging produces sentences: "user 7 logged in from 10.0.0.1". That's fine for humans, but hard for machines to search ("show me all logins for user 7"). Structured logging logs a message plus key/value attributes, and a handler renders them as text or JSON. Log systems like Loki, Datadog or CloudWatch can then filter on fields.

log/slog (Go 1.21+) is the standard way to do this. The main ideas:

  • Levels: Debug, Info, Warn, Error. A handler drops records below its minimum level.
  • Attributes: alternating key/value pairs ("port", 8080) or typed helpers (slog.Int("port", 8080)) which avoid mistakes and allocations.
  • Handlers: TextHandler (key=value) and JSONHandler. You can write your own.
  • logger.With(...) returns a child logger that adds fields to every line, like a request ID.
package main

import (
	"context"
	"log/slog"
	"os"
	"time"
)

// User implements slog.LogValuer so secrets never reach the logs.
type User struct {
	ID       int
	Email    string
	Password string
}

func (u User) LogValue() slog.Value {
	return slog.GroupValue(slog.Int("id", u.ID), slog.String("email", u.Email))
}

func main() {
	// Text handler: human friendly, good for local development.
	// ReplaceAttr drops the time key so this demo's output is stable.
	noTime := func(groups []string, a slog.Attr) slog.Attr {
		if a.Key == slog.TimeKey && len(groups) == 0 {
			return slog.Attr{}
		}
		return a
	}
	text := slog.New(slog.NewTextHandler(os.Stdout, &slog.HandlerOptions{ReplaceAttr: noTime}))
	text.Info("server starting", "port", 8080, "env", "dev")

	// JSON handler: machine friendly, what you ship to production.
	level := new(slog.LevelVar) // can be changed at runtime
	level.Set(slog.LevelDebug)
	logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
		Level:       level,
		ReplaceAttr: noTime,
	}))
	slog.SetDefault(logger) // package-level slog.Info etc. now use it

	slog.Debug("cache warmed", "entries", 1200)
	slog.Info("request done",
		slog.String("method", "GET"),
		slog.Int("status", 200),
		slog.Duration("took", 42*time.Millisecond),
	)

	// With: attach fields once, they appear on every line.
	reqLog := logger.With("request_id", "req-7f3a")
	reqLog.Warn("slow query", "table", "orders", "ms", 950)

	// Groups nest attributes under a key.
	reqLog.Error("payment failed", slog.Group("card", "brand", "visa", "last4", "4242"))

	// LogValuer in action: the password is never printed.
	slog.Info("login", "user", User{ID: 7, Email: "ada@example.com", Password: "hunter2"})

	// Raise the level at runtime: Debug lines now disappear.
	level.Set(slog.LevelWarn)
	slog.Info("you will not see this")
	slog.LogAttrs(context.Background(), slog.LevelWarn, "still visible", slog.Bool("fast_path", true))
}

Senior engineer tip

Pick key names once and stick to them across services (request_id, user_id, duration_ms): dashboards and alerts depend on them. Pass a *slog.Logger into your components (or use logger.With per request) instead of building messages with fmt.Sprintf. And never log secrets: implement LogValuer on types that hold them.

Mismatched pairs like slog.Info("x", "key") produce a !BADKEY attribute. go vet has a checker for this that runs by default, so keep vet in CI.

math/rand/v2

For non-cryptographic randomness (shuffling, jitter, sampling, simulations), use math/rand/v2. The top-level functions are automatically seeded and safe to call from many goroutines. Names follow a clear pattern: IntN(n) returns a value in [0, n). The generic rand.N works with any integer type, including time.Duration. For reproducible sequences, create your own generator with a fixed seed.

package main

import (
	"fmt"
	"math/rand/v2"
	"time"
)

func main() {
	// Top-level functions are auto-seeded and safe for concurrent use.
	fmt.Println("die roll 1-6:", rand.IntN(6)+1)
	fmt.Println("float in [0,1):", rand.Float64() < 1)
	fmt.Println("jitter:", rand.N(100*time.Millisecond) < 100*time.Millisecond) // generic N works with Duration

	// For reproducible results (tests, simulations) build your own seeded source.
	r := rand.New(rand.NewPCG(42, 1024))
	fmt.Println("seeded:", r.IntN(100), r.IntN(100), r.IntN(100))
	r2 := rand.New(rand.NewPCG(42, 1024))
	fmt.Println("same seed:", r2.IntN(100), r2.IntN(100), r2.IntN(100))

	deck := []string{"A", "K", "Q", "J", "10"}
	r.Shuffle(len(deck), func(i, j int) { deck[i], deck[j] = deck[j], deck[i] })
	fmt.Println("shuffled:", deck)
	fmt.Println("perm:", r.Perm(5))
}

Sorting: slices vs sort

Since Go 1.21, the slices package is the preferred way to sort. slices.Sort works on ordered types; slices.SortFunc takes a comparison function that returns negative, zero or positive. cmp.Compare builds those for you and cmp.Or chains "sort by this, then by that". The older sort package still works and you'll see it in existing code.

package main

import (
	"cmp"
	"fmt"
	"slices"
	"sort"
	"strings"
)

type Player struct {
	Name  string
	Score int
}

func main() {
	ps := []Player{{"ana", 70}, {"bo", 90}, {"cy", 70}, {"di", 85}}

	// Modern way: slices.SortFunc with cmp.Compare. Sort by score desc, then name.
	slices.SortFunc(ps, func(a, b Player) int {
		return cmp.Or(
			cmp.Compare(b.Score, a.Score), // descending
			strings.Compare(a.Name, b.Name),
		)
	})
	fmt.Println(ps)

	// Stable sort keeps the original order of equal elements.
	words := []string{"go", "is", "fun", "to", "write"}
	slices.SortStableFunc(words, func(a, b string) int { return cmp.Compare(len(a), len(b)) })
	fmt.Println(words)

	// Older but still common: sort.Slice with a less function.
	nums := []int{5, 2, 8, 1}
	sort.Slice(nums, func(i, j int) bool { return nums[i] < nums[j] })
	fmt.Println(nums, sort.IntsAreSorted(nums))

	// Binary search on sorted data.
	idx, found := slices.BinarySearch(nums, 5)
	fmt.Println("5 at", idx, found)
	i := sort.SearchInts(nums, 6) // insertion point
	fmt.Println("6 would go at", i)
}
  1. Four players. Two of them tie on 70.
  2. The comparator returns negative / zero / positive. cmp.Compare(b.Score, a.Score) has its arguments swapped, so higher scores sort first. cmp.Or returns the first non-zero result.
  3. For ana vs cy the scores tie (0), so cmp.Or falls through to the name comparison: "ana" < "cy" gives −1.
  4. Sorted in place: score descending, then name ascending.
  5. We sort by length only. The three 2-letter words are "equal", and the stable sort keeps their original order: go, is, to.
  6. sort.Slice takes a less function over indices, and the closure reads nums directly.
  7. Binary search needs sorted input. It halves the range each step and finds 5 at index 2.
  8. 6 is missing, so SearchInts returns the insertion point: the index of the first element ≥ 6, which is 8 at index 3.

os/exec: running other programs

exec.Command(name, args...) runs another program. Arguments are passed straight to the program, not through a shell, so there's no shell injection and no glob expansion: the "dangerous" string below is printed literally. Use exec.CommandContext so a hung child process gets killed when your timeout fires.

package main

import (
	"bytes"
	"context"
	"errors"
	"fmt"
	"os/exec"
	"strings"
	"time"
)

func main() {
	// Output runs the command and returns stdout.
	out, err := exec.Command("echo", "hello", "from", "a", "child").Output()
	fmt.Printf("out=%q err=%v\n", out, err)

	// Arguments are passed directly, NOT through a shell: no injection, no globbing.
	out, _ = exec.Command("echo", "$HOME; rm -rf /").Output()
	fmt.Printf("literal: %s", out)

	// Feed stdin and capture stdout/stderr separately.
	cmd := exec.Command("tr", "a-z", "A-Z")
	cmd.Stdin = strings.NewReader("shout please\n")
	var stdout, stderr bytes.Buffer
	cmd.Stdout, cmd.Stderr = &stdout, &stderr
	if err := cmd.Run(); err != nil {
		fmt.Println("run failed:", err)
	}
	fmt.Print("tr: ", stdout.String())

	// Non-zero exit codes come back as *exec.ExitError.
	err = exec.Command("ls", "/definitely/not/here").Run()
	var ee *exec.ExitError
	if errors.As(err, &ee) {
		fmt.Println("exit code:", ee.ExitCode())
	}

	// CommandContext kills the process when the context is done.
	ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
	defer cancel()
	err = exec.CommandContext(ctx, "sleep", "5").Run()
	fmt.Println("sleep:", err, "| ctx:", ctx.Err())

	// LookPath finds a binary on $PATH.
	_, err = exec.LookPath("no-such-binary-xyz")
	fmt.Println("lookpath:", err)
}

Danger

Never do exec.Command("sh", "-c", "convert " + userInput). That re-introduces shell injection. Pass each argument separately. If you truly need a shell pipeline, build it in Go with cmd.StdoutPipe() instead.

Putting it together: a real CLI tool

Let's build logq, a small tool that reads newline-delimited JSON logs (like the ones slog produces) and prints a summary. It uses most of this chapter: flag for options, os for files and exit codes, io.MultiReader to treat several files as one stream, bufio.Scanner for lines, encoding/json for parsing, time for filtering, slog for its own warnings on stderr, slices/maps for sorting, and a buffered writer for output.

Design goals that make it production-shaped:

  • Data to stdout, diagnostics to stderr. So logq app.log > report.txt doesn't mix warnings into the report.
  • A run function with injected I/O. main is three lines. Everything else takes args, stdin, stdout, stderr as parameters, so tests can drive it.
  • Exit codes. 0 on success, 1 on error, so it composes in shell scripts.
  • Tolerant input. Bad lines are counted and reported, not fatal.
// logq summarizes newline-delimited JSON logs.
//
//	usage: logq [-level warn] [-after 2026-10-16T09:00:00Z] [-json] [file ...]
package main

import (
	"bufio"
	"cmp"
	"encoding/json"
	"errors"
	"flag"
	"fmt"
	"io"
	"log/slog"
	"maps"
	"os"
	"slices"
	"strings"
	"time"
)

type entry struct {
	Time  time.Time `json:"time"`
	Level string    `json:"level"`
	Msg   string    `json:"msg"`
}

type summary struct {
	Lines    int            `json:"lines"`
	Matched  int            `json:"matched"`
	Skipped  int            `json:"skipped"`
	ByLevel  map[string]int `json:"by_level"`
	TopMsgs  []msgCount     `json:"top_messages"`
	First    time.Time      `json:"first,omitzero"`
	Last     time.Time      `json:"last,omitzero"`
	Duration string         `json:"span,omitempty"`
}

type msgCount struct {
	Msg   string `json:"msg"`
	Count int    `json:"count"`
}

var rank = map[string]int{"debug": 0, "info": 1, "warn": 2, "error": 3}

func main() {
	if err := run(os.Args[1:], os.Stdin, os.Stdout, os.Stderr); err != nil {
		fmt.Fprintln(os.Stderr, "logq:", err)
		os.Exit(1)
	}
}

// run holds all the logic so it is testable: no globals, no os.Exit.
func run(args []string, stdin io.Reader, stdout, stderr io.Writer) error {
	fs := flag.NewFlagSet("logq", flag.ContinueOnError)
	fs.SetOutput(stderr)
	minLevel := fs.String("level", "debug", "minimum level: debug|info|warn|error")
	after := fs.String("after", "", "only entries after this RFC3339 time")
	asJSON := fs.Bool("json", false, "print the summary as JSON")
	top := fs.Int("top", 3, "how many top messages to show")
	if err := fs.Parse(args); err != nil {
		return err
	}

	minRank, ok := rank[strings.ToLower(*minLevel)]
	if !ok {
		return fmt.Errorf("unknown level %q", *minLevel)
	}
	var cutoff time.Time
	if *after != "" {
		t, err := time.Parse(time.RFC3339, *after)
		if err != nil {
			return fmt.Errorf("bad -after: %w", err)
		}
		cutoff = t
	}

	log := slog.New(slog.NewTextHandler(stderr, &slog.HandlerOptions{
		ReplaceAttr: func(_ []string, a slog.Attr) slog.Attr {
			if a.Key == slog.TimeKey {
				return slog.Attr{}
			}
			return a
		},
	}))

	// Inputs: named files, or stdin when none are given.
	var readers []io.Reader
	for _, name := range fs.Args() {
		f, err := os.Open(name)
		if err != nil {
			return err
		}
		defer f.Close()
		readers = append(readers, f)
	}
	if len(readers) == 0 {
		readers = append(readers, stdin)
	}

	s := summary{ByLevel: map[string]int{}}
	counts := map[string]int{}
	sc := bufio.NewScanner(io.MultiReader(readers...))
	for sc.Scan() {
		s.Lines++
		var e entry
		if err := json.Unmarshal(sc.Bytes(), &e); err != nil {
			s.Skipped++
			log.Warn("skipping bad line", "line", s.Lines, "err", err)
			continue
		}
		if rank[e.Level] < minRank || (!cutoff.IsZero() && !e.Time.After(cutoff)) {
			continue
		}
		s.Matched++
		s.ByLevel[e.Level]++
		counts[e.Msg]++
		if s.First.IsZero() || e.Time.Before(s.First) {
			s.First = e.Time
		}
		if e.Time.After(s.Last) {
			s.Last = e.Time
		}
	}
	if err := sc.Err(); err != nil {
		return fmt.Errorf("reading input: %w", err)
	}
	if s.Matched == 0 {
		return errors.New("no entries matched")
	}

	for _, m := range slices.Sorted(maps.Keys(counts)) {
		s.TopMsgs = append(s.TopMsgs, msgCount{m, counts[m]})
	}
	slices.SortStableFunc(s.TopMsgs, func(a, b msgCount) int { return cmp.Compare(b.Count, a.Count) })
	s.TopMsgs = s.TopMsgs[:min(*top, len(s.TopMsgs))]
	s.Duration = s.Last.Sub(s.First).String()

	if *asJSON {
		enc := json.NewEncoder(stdout)
		enc.SetIndent("", "  ")
		return enc.Encode(s)
	}
	w := bufio.NewWriter(stdout)
	defer w.Flush()
	fmt.Fprintf(w, "lines=%d matched=%d skipped=%d span=%s\n", s.Lines, s.Matched, s.Skipped, s.Duration)
	for _, lvl := range []string{"debug", "info", "warn", "error"} {
		if n := s.ByLevel[lvl]; n > 0 {
			fmt.Fprintf(w, "  %-6s %3d %s\n", lvl, n, strings.Repeat("#", n))
		}
	}
	fmt.Fprintln(w, "top messages:")
	for _, mc := range s.TopMsgs {
		fmt.Fprintf(w, "  %3d  %s\n", mc.Count, mc.Msg)
	}
	return nil
}

Exercise 1: a word-frequency counter

Write a program that reads text from stdin and prints the 3 most common words (lower-cased) with their counts, most common first, breaking ties alphabetically. Hint: bufio.Scanner with bufio.ScanWords, a map[string]int, and slices.SortFunc with cmp.Or.

Solution
package main

import (
	"bufio"
	"cmp"
	"fmt"
	"os"
	"slices"

Exercise 2: CSV to JSON converter

Read a CSV with a header row and print it as a JSON array of objects, using the header names as keys. Numbers should stay strings (CSV has no types). Make it a func convert(r io.Reader, w io.Writer) error so it is testable. Hint: csv.NewReader, a []map[string]string, and json.NewEncoder(w).

Solution
package main

import (
	"encoding/csv"
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"os"
	"strings"
)

func convert(r io.Reader, w io.Writer) error {
	cr := csv.NewReader(r)
	header, err := cr.Read()
	if err != nil {
		return fmt.Errorf("reading header: %w", err)
	}
	var rows []map[string]string
	for {
		rec, err := cr.Read()
		if errors.Is(err, io.EOF) {
			break
		}
		if err != nil {
			return err
		}
		row := make(map[string]string, len(header))
		for i, h := range header {
			row[h] = rec[i]
		}
		rows = append(rows, row)
	}
	enc := json.NewEncoder(w)
	enc.SetIndent("", "  ")
	return enc.Encode(rows)
}

func main() {
	in := "name,lang\nAda,Go\nGrace,COBOL\n"
	if err := convert(strings.NewReader(in), os.Stdout); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
}
  1. main hands convert a strings.Reader and os.Stdout. convert only sees the interfaces, so a test could pass a bytes.Buffer instead.
  2. Inside convert, the header row gives us the keys. If that fails, we wrap the error with context using %w.
  3. A nil slice. append will allocate it as needed.
  4. First record. We zip header[i] with rec[i] into a fresh map and append it.
  5. Second record. Each row is a new map. Reusing one map would make every element point to the same data.
  6. io.EOF breaks the loop.
  7. The encoder streams straight to w. Notice "lang" comes before "name": encoding/json sorts map keys, so the output is deterministic even though map iteration order isn't.
  8. Encode returns nil, and so does convert. main skips the error branch and exits 0.

Key takeaways

  • io.Reader / io.Writer are the universal plugs. Accept them in your APIs and compose them with Copy, TeeReader, MultiWriter, LimitReader.
  • Use bufio.Scanner for lines (check Err(), raise Buffer for long lines) and always Flush() a bufio.Writer or csv.Writer.
  • File errors are typed: check with errors.Is(err, fs.ErrNotExist). Check the error from Close on files you write. Use temp-file-plus-rename for atomic writes.
  • os.Exit skips defers: keep logic in run() error and exit only in main.
  • Use filepath.Join and WalkDir; never concatenate paths with slashes.
  • JSON: tags control keys; omitzero (1.24+) fixes zero structs and times; unknown JSON numbers are float64; stream with json.Decoder; reject typos with DisallowUnknownFields.
  • Time layouts are written with the reference date 2006-01-02 15:04:05. Compare with Equal, measure with time.Since (monotonic).
  • Use log/slog with a JSON handler in production, consistent keys, With for request context, and LogValuer to hide secrets.
  • math/rand/v2 for simulations, crypto/rand for secrets; slices.SortFunc + cmp for sorting; exec.CommandContext without a shell; embed to ship assets in the binary.
