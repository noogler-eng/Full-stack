Strings, Bytes & Runes

Text is everywhere: names, logs, JSON, URLs, user input. Go's strings are simple on the surface but have one twist that trips everyone up at first: a string is a sequence of bytes, not characters. Once you understand bytes, runes and UTF-8, the rest of Go's text tools (the strings, strconv, fmt and unicode packages) fall neatly into place.

What a string really is

In Go, a string is a read-only sequence of bytes. That's it. Under the hood it's a tiny two-word header, much like a slice header but without capacity: a pointer to the bytes and a length.

Two consequences follow straight away:

  • Strings are immutable. Once created, the bytes can never change. You can't do s[0] = 'H'. Every "modification" (ToUpper, Replace, +) creates a brand-new string.
  • Copying a string is cheap. Assigning or passing a string copies only the 16-byte header. Because nobody can change the bytes, it's perfectly safe for many strings to share them. Slicing a string (s[2:5]) also shares the bytes, with no copying.
package main

func main() {
	s := "hello"
	s[0] = 'H'
}
./main.go:5:2: cannot assign to s[0] (neither addressable nor a map index expression)

If you need to change text in place, convert to a []byte or []rune (which makes a mutable copy), change it, then convert back.

Mental model

A string is like a printed page: you can read it, photocopy it, or cut out a section to look at, but you can't erase a letter. To edit, you retype the page (build a new string). That restriction is what lets Go share string memory freely and safely between goroutines.

UTF-8 in one minute

Computers store numbers, so text needs an encoding: a rule for turning characters into bytes. Unicode gives every character in every writing system a number called a code point, written like U+0041 for "A" or U+1F439 for 🐹. UTF-8 is the encoding that turns those numbers into 1 to 4 bytes:

Code point rangeBytesExamples
U+0000 – U+007F1ASCII: A, z, 7, {
U+0080 – U+07FF2Accented Latin, Greek, Cyrillic: é, Ω, ж
U+0800 – U+FFFF3Most CJK, symbols: 中, €, ✓
U+10000 – U+10FFFF4Emoji, rare scripts: 🐹, 𝄞

UTF-8's genius is that plain ASCII text is already valid UTF-8, byte for byte. Go source code is defined to be UTF-8, so string literals in your code are UTF-8 too. (Fun fact: UTF-8 was designed by Ken Thompson and Rob Pike, two of Go's creators.)

Bytes vs runes: len, indexing and range

Because a string is bytes, the built-in operations work on bytes:

package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	ascii := "Go"
	accented := "café"
	emoji := "Go🐹"

	// len counts BYTES, not characters.
	fmt.Println(len(ascii), len(accented), len(emoji))

	// Count characters (runes) with utf8.RuneCountInString.
	fmt.Println(utf8.RuneCountInString(ascii),
		utf8.RuneCountInString(accented),
		utf8.RuneCountInString(emoji))

	// Indexing gives a single BYTE (type byte = uint8).
	fmt.Println(accented[0], accented[3], accented[4])
	fmt.Printf("%c %T\n", accented[0], accented[0])

	// Slicing is by byte offsets too. Cutting inside é breaks it.
	fmt.Println(accented[:3], accented[:4], accented[:5])

	// The bytes behind the text:
	fmt.Printf("% x\n", accented)
}
  1. Three strings. Each one is just a read-only sequence of UTF-8 bytes.
  2. len counts bytes. "é" needs 2 bytes and the hamster needs 4.
  3. utf8.RuneCountInString decodes the bytes and counts code points: the number you'd call "characters".
  4. Indexing returns one byte, printed as a number. Bytes 3 and 4 are the two halves of é (0xc3 0xa9).
  5. %c shows byte 99 as 'c', and %T confirms its type is uint8 (that's what byte is).
  6. Slicing is by byte offsets. [:4] cuts é in half, leaving a lone 0xc3 that prints as the replacement character.
  7. % x prints the raw bytes in hex with spaces: c, a, f, then é's two bytes.

Read that output carefully, because it's the heart of this chapter:

  • len("café") is 5, not 4: "é" takes two bytes (c3 a9). The hamster emoji takes four.
  • accented[3] is 195 (0xc3), the first half of é. Indexing gives a byte (an alias for uint8), never a character.
  • accented[:4] slices through the middle of é, leaving an invalid byte that prints as the replacement character �.

To work with characters, use for range. On a string, range decodes UTF-8 for you and yields each rune together with the byte offset where it starts:

s := "héy"
for i := 0; i < len(s); i++ {
	fmt.Print(s[i], " ")
}
fmt.Println()
for i, r := range s {
	fmt.Printf("%d:%c ", i, r)
}
fmt.Println()
  1. Three characters, but é is 2 bytes, so len(s) is 4.
  2. A classic index loop goes byte by byte. s[0] is 104, the byte for 'h'. Printing a byte prints the number.
  3. Byte 1 is 0xc3: the first half of é. Not a character on its own.
  4. Byte 2 is 0xa9: the second half of é.
  5. Byte 3 is 'y'. Four iterations for three characters; Println ends the line.
  6. Now range. It decodes one rune at a time. First: offset 0, rune 'h'.
  7. Offset 1. range read two bytes and decoded them into the single rune é.
  8. Offset jumps to 3 (skipping 2). Three iterations for three characters.
104 195 169 121 
0:h 1:é 3:y
Gotcha: "character" is fuzzier than you think

A rune is a Unicode code point, which is usually but not always what a human calls a character. "é" can also be written as "e" plus a combining accent (two runes), and many emoji like 👍🏽 or family emoji are several runes joined together. If you need true user-perceived characters ("grapheme clusters"), for example to truncate a display name, use a library such as github.com/rivo/uniseg. For most backend work, runes are the right unit.

The byte and rune types

Go has two aliases for working with text:

  • byte is exactly uint8: one raw byte.
  • rune is exactly int32: one Unicode code point. A rune literal is written in single quotes: 'a', 'é', '\n', 'é'.

Single quotes make a rune (a number). Double quotes make a string. 'a' and "a" are different types.

package main

import "fmt"

func main() {
	var b byte = 'A' // byte is an alias for uint8
	var r rune = 'é' // rune is an alias for int32: one Unicode code point
	fmt.Println(b, r)
	fmt.Printf("%c %c %U\n", b, r, r)

	s := "naïve"

	// []byte: a mutable copy of the raw bytes.
	bs := []byte(s)
	bs[0] = 'N'
	fmt.Println(string(bs), len(bs))

	// []rune: decode into code points. Safe for per-character work.
	rs := []rune(s)
	rs[2] = 'i'
	fmt.Println(string(rs), len(rs))

	// A single rune to string:
	fmt.Println(string(rune(0x1F439)), string('x'))

	// Reverse by runes (bytes would break multi-byte characters).
	for i, j := 0, len(rs)-1; i < j; i, j = i+1, j-1 {
		rs[i], rs[j] = rs[j], rs[i]
	}
	fmt.Println(string(rs))
}
  1. Rune literals are numbers. 'A' fits in a byte (65); 'é' is code point 233, stored in an int32.
  2. Println shows them as plain numbers.
  3. %c prints the character and %U the Unicode notation.
  4. []byte(s) copies the raw UTF-8 bytes into a new, mutable slice. "ï" takes two of them.
  5. Changing bs[0] is safe because 'n' is a single byte. The original s is untouched: strings are immutable.
  6. []rune(s) decodes into code points instead: one element per character, 5 in total.
  7. Now index 2 really is "ï", so replacing it with 'i' works cleanly.
  8. string(rune(...)) encodes one code point back to UTF-8.
  9. Reversing by runes: swap the ends. First swap: 'n' and 'e'.
  10. Second swap: 'a' and 'v'. Next, i and j both become 2, so the loop stops.
  11. Reversing bytes instead would have split multi-byte characters and produced garbage.

Invalid UTF-8

A Go string can hold any bytes, not just valid UTF-8, for example data read from a binary file. When range hits a byte that isn't valid UTF-8, it yields the special rune U+FFFD (the replacement character �) and moves forward one byte. The unicode/utf8 package helps you check and decode:

package main

import (
	"fmt"
	"strings"
	"unicode/utf8"
)

func main() {
	bad := "ok\xffok" // \xff is not valid UTF-8
	fmt.Println(utf8.ValidString(bad), utf8.ValidString("héllo"))

	for i, r := range bad {
		fmt.Printf("%d:%q ", i, r) // invalid bytes decode as U+FFFD
	}
	fmt.Println()

	fmt.Println(strings.ToValidUTF8(bad, "?"))

	// Decode one rune at a time and learn its size in bytes.
	s := "€5"
	r, size := utf8.DecodeRuneInString(s)
	fmt.Println(string(r), size, utf8.RuneLen('€'))
}
  1. A string can hold any bytes. \xff is a single byte that is never valid UTF-8.
  2. utf8.ValidString checks the whole string: bad fails, "héllo" passes.
  3. range decodes the first two bytes as normal runes.
  4. At byte 2 it can't decode anything, so it yields the replacement rune U+FFFD and advances by exactly one byte. No panic.
  5. The rest decodes normally, and Println ends the line.
  6. strings.ToValidUTF8 replaces each run of invalid bytes with the string you choose.
  7. utf8.DecodeRuneInString decodes just the first rune and tells you how many bytes it used: 3 for €.
  8. utf8.RuneLen answers the reverse question: how many bytes would this rune need?

0:'o' 1:'k' 2:'�' 3:'o' 4:'k'

len counts bytes: G and o are 1 byte each and 🐹 is 4, so 6. range decodes runes, so it runs 3 times (offsets 0, 1 and 2).
Senior engineer tip

Be explicit about units whenever a limit involves text. "Username max 20" should say whether it means bytes (what your database column may count), runes, or displayed characters. Truncating with s[:20] can cut a character in half and store invalid UTF-8. To truncate safely by runes, walk with range and cut at a byte offset it gives you, or use utf8.ValidString to check after cutting.

String literals: interpreted and raw

Go has two kinds of string literal:

  • Interpreted literals use double quotes. Backslash escapes are processed: \n (newline), \t (tab), \", \\, é (a code point), \xff (a raw byte).
  • Raw literals use backticks. Everything between them is taken literally, including backslashes and newlines. The only thing you can't put inside is a backtick.
package main

import (
	"fmt"
	"regexp"
)

func main() {
	// Interpreted literal: escape sequences are processed.
	a := "line one\nline two\t(tabbed) \"quoted\" \u00e9"
	fmt.Println(a)

	// Raw literal (backticks): exactly what you type, across lines.
	b := `C:\Users\gopher\n is not a newline here
second line, "quotes" need no escaping`
	fmt.Println(b)

	// Raw strings shine for regexps, JSON, SQL and templates.
	re := regexp.MustCompile(`^\d{3}-\d{4}$`)
	fmt.Println(re.MatchString("555-1234"))

	query := `
SELECT id, name
FROM users
WHERE active = true`
	fmt.Println(len(query) > 0)
}

Use raw strings for regular expressions (no double-escaping \\d), Windows paths, multi-line SQL, JSON test fixtures, and templates. One small trap: a raw string spanning multiple lines includes the leading newline and the indentation of each line, exactly as typed.

A tour of the strings package

The strings package is where you'll spend most of your text-processing time. All its functions take strings and return new strings (remember, strings are immutable). Here's a big sampler. Don't memorise it; skim it so you know what exists:

package main

import (
	"fmt"
	"strings"
	"unicode"
	"unicode/utf8"
)

func main() {
	s := "  The quick brown fox  "

	// Searching
	fmt.Println(strings.Contains(s, "quick"), strings.ContainsAny(s, "xyz"))
	fmt.Println(strings.HasPrefix("main.go", "main"), strings.HasSuffix("main.go", ".go"))
	fmt.Println(strings.Index("chicken", "ken"), strings.LastIndex("go gopher", "go"))
	fmt.Println(strings.Count("cheese", "e"), strings.EqualFold("Go", "GO"))

	// Cleaning up
	fmt.Printf("%q\n", strings.TrimSpace(s))
	fmt.Printf("%q\n", strings.Trim("--x--", "-"))
	fmt.Println(strings.TrimPrefix("v1.2.3", "v"), strings.TrimSuffix("app.log", ".log"))

	// Splitting and joining
	fmt.Printf("%q\n", strings.Split("a,b,,c", ","))
	fmt.Printf("%q\n", strings.Fields(s)) // splits on any run of whitespace
	fmt.Printf("%q\n", strings.SplitN("k=v=w", "=", 2))
	fmt.Println(strings.Join([]string{"usr", "local", "bin"}, "/"))

	// Cut (Go 1.18+): split around the FIRST separator.
	key, val, found := strings.Cut("timeout=30s", "=")
	fmt.Println(key, val, found)
	before, found := strings.CutPrefix("Bearer abc123", "Bearer ")
	fmt.Println(before, found)

	// Transforming
	fmt.Println(strings.ToUpper("gopher"), strings.ToLower("GoLang"))
	fmt.Println(strings.Replace("oink oink oink", "k", "ky", 2))
	fmt.Println(strings.ReplaceAll("oink oink", "oink", "moo"))
	fmt.Println(strings.Repeat("ab", 3) + strings.Repeat("-", 5))
	r := strings.NewReplacer("<", "&lt;", ">", "&gt;")
	fmt.Println(r.Replace("<b>hi</b>"))
	fmt.Println(strings.Map(func(r rune) rune {
		if unicode.IsDigit(r) {
			return -1 // drop the rune
		}
		return r
	}, "a1b2c3"))

	// Iterators (Go 1.24): no intermediate slice.
	for part := range strings.SplitSeq("x|y|z", "|") {
		fmt.Print(part, " ")
	}
	fmt.Println()

	// strings.Title is deprecated. A simple ASCII-friendly alternative:
	fmt.Println(titleWords("hello wide world"))
}

func titleWords(s string) string {
	words := strings.Fields(s)
	for i, w := range words {
		r, size := utf8.DecodeRuneInString(w)
		words[i] = string(unicode.ToTitle(r)) + w[size:]
	}
	return strings.Join(words, " ")
}

Highlights and things to watch for:

  • Split vs Fields: Split(s, ",") splits on an exact separator and keeps empty pieces (note the "" from ,,). Fields(s) splits on any run of whitespace and never returns empty pieces. For user input, Fields is usually what you want.
  • Cut is the cleanest way to split "key=value" pairs. It returns before, after and whether the separator was found. Prefer it over Split + index juggling.
  • EqualFold compares case-insensitively and Unicode-correctly. It's better than ToLower(a) == ToLower(b), which allocates two strings.
  • Trim vs TrimPrefix: Trim(s, "-") removes any of the characters in the cutset from both ends, repeatedly. TrimPrefix(s, "v") removes one exact prefix once. Mixing them up is a common bug: strings.Trim("version", "version.") leaves nothing.
  • NewReplacer does many replacements in a single pass, and is safe to reuse across goroutines.
  • SplitSeq, FieldsSeq, Lines (Go 1.24) return iterators, so you can loop over pieces without allocating a slice.
  • strings.Title is deprecated: it doesn't handle Unicode word boundaries properly. For real-world title casing use golang.org/x/text/cases (cases.Title(language.English).String(s)). For simple ASCII-ish cases, the small titleWords helper above works.

Split keeps empty strings between consecutive separators. If you want to drop empties, filter them out, or use Fields/FieldsFunc when splitting on whitespace-like characters.

Parsing a line: Cut, TrimSpace and strconv together

Parsing config lines, headers or simple protocols is one of the most common string jobs. Here's the bread-and-butter combination:

line := " port = 8080 "
key, val, ok := strings.Cut(line, "=")
key = strings.TrimSpace(key)
val = strings.TrimSpace(val)
fmt.Printf("%q %q %t\n", key, val, ok)
port, err := strconv.Atoi(val)
fmt.Println(port+1, err)
_, err = strconv.Atoi("80a")
fmt.Println(err)
  1. Messy input with spaces around everything.
  2. Cut splits around the first "=". Both halves still carry spaces. No allocation: they are sub-slices of line.
  3. TrimSpace strips leading and trailing whitespace (spaces, tabs, newlines). Again just re-slicing.
  4. %q prints with quotes, so stray whitespace would be visible. Great for debugging.
  5. strconv.Atoi turns the text into an int. Now we can do arithmetic.
  6. Bad input gives a descriptive error instead of a crash. Always check it.

Building strings efficiently

Since strings are immutable, s += "x" can't append in place. It allocates a new string big enough for both parts and copies everything into it. Do that in a loop and you copy the growing string over and over: 1 byte, then 2, then 3... For n additions that's about n²/2 bytes copied. This is called quadratic behaviour, and it gets slow fast.

strings.Builder fixes this. It keeps a growable []byte internally (growing like a slice, by doubling) and only turns it into a string at the very end, without a final copy. Let's measure:

package main

import (
	"strings"
	"testing"
)

const n = 1000

func BenchmarkPlusEquals(b *testing.B) {
	for b.Loop() {
		s := ""
		for range n {
			s += "x"
		}
		_ = s
	}
}

func BenchmarkBuilder(b *testing.B) {
	for b.Loop() {
		var sb strings.Builder
		for range n {
			sb.WriteString("x")
		}
		_ = sb.String()
	}
}

func BenchmarkBuilderGrow(b *testing.B) {
	for b.Loop() {
		var sb strings.Builder
		sb.Grow(n)
		for range n {
			sb.WriteString("x")
		}
		_ = sb.String()
	}
}

  1. The zero value of a Builder is ready to use. No constructor needed.
  2. Grow(16) reserves room for 16 bytes up front, so the next writes won't need to reallocate.
  3. WriteString appends bytes into the buffer. Nothing is copied into a string yet.
  4. WriteByte adds one byte.
  5. WriteRune encodes ✓ (U+2713) as UTF-8: three bytes. Length jumps by 3.
  6. Builder implements io.Writer, so fmt.Fprintf can format straight into it.
  7. 12 bytes used, still within the 16 we reserved. Zero reallocations.
  8. String() returns the result without copying the buffer (it's safe because the Builder never modifies bytes it has already handed out).

A realistic use, building a small text table:

package main

import (
	"fmt"
	"strings"
)

type Item struct {
	Name  string
	Price float64
}

func renderTable(items []Item) string {
	var sb strings.Builder
	sb.WriteString("NAME       PRICE\n")
	for _, it := range items {
		// fmt.Fprintf writes into any io.Writer, including a Builder.
		fmt.Fprintf(&sb, "%-10s %5.2f\n", it.Name, it.Price)
	}
	sb.WriteString(strings.Repeat("-", 16))
	return sb.String()
}

func main() {
	fmt.Println(renderTable([]Item{{"coffee", 3.5}, {"bagel", 2.25}, {"juice", 4}}))
}
  1. main calls renderTable with three items. Nothing prints until the whole table is built.
  2. A zero-value Builder is ready to use. The header line goes in first: 16 characters plus a newline.
  3. Fprintf formats straight into the Builder. %-10s left-aligns the name in 10 columns; %5.2f right-aligns the price with 2 decimals.
  4. Same format for every row, so the columns line up.
  5. 4 becomes 4.00 because of the .2 precision.
  6. A ruler of 16 dashes, then String() hands back the result without copying the buffer.
  7. Back in main, a single Println writes the finished table.

Don't over-correct: a + " " + b on one line is perfectly fine. The compiler joins a single expression in one allocation. The Builder matters in loops or when assembling many pieces. Also, if you're building output that goes to a file, a socket or an HTTP response, skip the string entirely and write straight to the io.Writer (wrapped in a bufio.Writer for many small writes). And never copy a non-zero strings.Builder by value; it panics, by design.

The bytes package

The bytes package is the twin of strings, for []byte. It has Contains, Split, Fields, TrimSpace, ToUpper and friends with the same names and behaviour. Use it when your data is already bytes (file contents, network buffers, HTTP bodies), to avoid converting to a string and back. It also has bytes.Buffer, a growable buffer you can both write to and read from:

package main

import (
	"bytes"
	"fmt"
	"os"
)

func main() {
	data := []byte("  Hello, Bytes!  ")

	// The bytes package mirrors strings, for []byte.
	fmt.Println(bytes.Contains(data, []byte("Bytes")))
	fmt.Printf("%q\n", bytes.TrimSpace(data))
	fmt.Printf("%q\n", bytes.ToUpper(data))
	fmt.Println(bytes.Equal([]byte("a"), []byte("a"))) // slices can't use ==

	fields := bytes.Fields([]byte("a b  c"))
	fmt.Println(len(fields), string(bytes.Join(fields, []byte("+"))))

	// bytes.Buffer: a growable buffer you can write to AND read from.
	var buf bytes.Buffer
	buf.WriteString("first line\n")
	fmt.Fprintf(&buf, "number %d\n", 7)
	line, _ := buf.ReadString('\n') // read consumes from the front
	fmt.Printf("read %q, %d bytes left\n", line, buf.Len())
	buf.WriteTo(os.Stdout)
}
  1. Our data is already a []byte, as if read from a file or socket.
  2. bytes.Contains works like strings.Contains, without converting to a string first.
  3. TrimSpace and ToUpper have the same names and behaviour as in strings.
  4. Slices can't be compared with ==, so bytes.Equal compares contents.
  5. Fields splits on runs of whitespace (the double space makes no empty piece); Join glues them back.
  6. A zero-value bytes.Buffer is ready to write to. Fprintf works because it's an io.Writer.
  7. Unlike a Builder, a Buffer can be read. ReadString('\n') consumes bytes from the front up to and including the newline.
  8. %q shows the newline as \n. 9 unread bytes remain.
  9. WriteTo drains what's left straight into os.Stdout.

strconv: converting to and from text

The strconv ("string conversion") package converts between strings and basic types. It's faster and stricter than fmt.Sscanf, and its error messages tell you exactly what went wrong.

package main

import (
	"fmt"
	"strconv"
)

func main() {
	// String -> number
	n, err := strconv.Atoi("123")
	fmt.Println(n+1, err)

	_, err = strconv.Atoi("12a")
	fmt.Println(err)

	f, _ := strconv.ParseFloat("3.14159", 64)
	fmt.Println(f * 2)

	b, _ := strconv.ParseBool("true")
	fmt.Println(b)

	// ParseInt lets you choose the base and bit size.
	hex, _ := strconv.ParseInt("ff", 16, 64)
	bin, _ := strconv.ParseInt("-1010", 2, 64)
	fmt.Println(hex, bin)
	_, err = strconv.ParseInt("300", 10, 8) // doesn't fit in int8
	fmt.Println(err)

	// Number -> string
	fmt.Println(strconv.Itoa(42) + "!")
	fmt.Println(strconv.FormatInt(255, 2), strconv.FormatInt(255, 16))
	fmt.Println(strconv.FormatFloat(1.5, 'f', 3, 64), strconv.FormatFloat(1234567.0, 'e', 2, 64))

	// Quote / Unquote: Go-syntax string literals.
	q := strconv.Quote("tab\there \"hi\" é")
	fmt.Println(q)
	fmt.Println(strconv.QuoteToASCII("é🐹"))
	u, _ := strconv.Unquote(q)
	fmt.Println(u)

	// Common mistake: string(n) is NOT a number conversion.
	fmt.Println(string(rune(65)), strconv.Itoa(65))
}
  1. Atoi parses a decimal int. With err == nil we can safely do arithmetic.
  2. One stray letter and the whole parse fails, with a message naming the function and the input. No partial "12".
  3. ParseFloat and ParseBool follow the same (value, error) shape. Here we ignore the errors with _ only because the inputs are constants.
  4. ParseInt takes a base: "ff" in base 16 is 255, "-1010" in base 2 is -10.
  5. The bit size 8 means "must fit in an int8" (-128..127). 300 doesn't, so we get a range error. The returned number would be clamped to 127, which is why you never use it without checking err.
  6. Going the other way: Itoa for decimal, FormatInt for any base.
  7. FormatFloat takes a format byte ('f', 'e', 'g') and a precision: 3 decimals, then 2-digit scientific notation.
  8. Quote produces a Go string literal: quotes around it, the tab and inner quotes escaped. Handy for logging untrusted text.
  9. QuoteToASCII also escapes every non-ASCII rune.
  10. Unquote reverses it, so the real tab character comes back.
  11. The classic mix-up: string(rune(65)) is the character with code point 65, "A". For digits you want strconv.Itoa.

fmt: formatting verbs

The fmt package formats values using verbs: placeholders starting with % inside a format string. You've used Println, which needs no verbs. Printf, Sprintf, Fprintf and Errorf all take a format string. Here's every verb you'll realistically need, each printed next to its result:

package main

import "fmt"

type Point struct {
	X, Y int
}

func main() {
	p := Point{1, 2}
	fmt.Printf("%%v   %v\n", p)
	fmt.Printf("%%+v  %+v\n", p)
	fmt.Printf("%%#v  %#v\n", p)
	fmt.Printf("%%T   %T\n", p)

	fmt.Printf("%%d %d | %%b %b | %%o %o | %%x %x | %%X %X\n", 42, 42, 42, 42, 42)
	fmt.Printf("%%c %c | %%q %q | %%U %U\n", 'G', 'G', 'G')

	fmt.Printf("%%f %f | %%.2f %.2f | %%e %e | %%g %g\n", 3.14159, 3.14159, 3.14159, 3.14159)
	fmt.Printf("[%%08.3f] [%08.3f]\n", 3.14159)

	fmt.Printf("%%s %s | %%q %q | %%x %x\n", "go", "go", "go")

	// Width and alignment
	fmt.Printf("[%%5d]   [%5d]\n", 42)
	fmt.Printf("[%%-5d]  [%-5d]\n", 42)
	fmt.Printf("[%%05d]  [%05d]\n", 42)
	fmt.Printf("[%%10s]  [%10s]\n", "right")
	fmt.Printf("[%%-10s] [%-10s]\n", "left")
	fmt.Printf("[%%.3s]  [%.3s]\n", "truncate")
	fmt.Printf("[%%*d]   [%*d]\n", 6, 7) // width from an argument

	fmt.Printf("%[1]d %[1]x %[1]o %[2]s\n", 64, "again")

	// Mistakes are reported in the output, not as panics:
	fmt.Printf("%d %s\n", "oops", 5)

The general shape of a verb is %[flags][width][.precision]verb. Flags are - (left-align), 0 (zero-pad), + (always show sign), space (leave room for sign) and # (alternate form, e.g. %#x → 0x2a). Once you know that shape you can read any format string.

Sprintf, Fprintf and Errorf

The fmt functions come in families. The prefix says where the output goes, the suffix says how it's formatted:

  • Print/Println/Printf: to standard output.
  • Sprint/Sprintln/Sprintf: return a string.
  • Fprint/Fprintln/Fprintf: to any io.Writer (file, buffer, HTTP response...).
  • Errorf: returns an error; supports %w to wrap another error.
package main

import (
	"errors"
	"fmt"
	"io/fs"
	"os"
)

func main() {
	// Sprintf returns the formatted string.
	msg := fmt.Sprintf("user %q has %d items", "ann", 3)
	fmt.Println(msg)

	// Fprintf writes to any io.Writer: a file, a network conn, a buffer...
	fmt.Fprintf(os.Stdout, "to stdout: %.1f%%\n", 99.5)
	fmt.Fprintln(os.Stderr, "this goes to stderr")

	// Errorf builds errors; %w wraps an underlying error.
	_, err := os.Open("/no/such/file")
	wrapped := fmt.Errorf("loading config: %w", err)
	fmt.Println(wrapped)
	fmt.Println(errors.Is(wrapped, fs.ErrNotExist))

	// Sprint / Sprintln: no verbs, just values.
	fmt.Println(fmt.Sprint("a", 1, 2, "b"), fmt.Sprintln("x", 1) == "x 1\n")
}
  1. Sprintf doesn't print anything: it returns the formatted string. %q adds the quotes around ann.
  2. Fprintf writes to whatever io.Writer you give it. %.1f keeps one decimal, and %% is a literal percent sign.
  3. Same family, different destination: standard error. (The terminal shows both streams, which is why it appears in the combined output.)
  4. Opening a missing file returns an *fs.PathError.
  5. Errorf with %w builds a new error whose message adds context in front of the original.
  6. Because %w wraps rather than just formats, errors.Is can still find the underlying "not exist" error inside. With %v this would be false.
  7. Sprint adds a space only between two non-string operands (1 and 2), giving a1 2b. Sprintln always adds spaces and a trailing newline.

a1 2b true

A subtle point about Sprint("a", 1, 2, "b"): it adds a space only between two operands when neither is a string, which is why you get a1 2b. Sprintln always adds spaces. When in doubt, use Sprintf and be explicit.

Senior engineer tip

Implement String() string on your important types (that makes them fmt.Stringer) so %v and %s print something meaningful. But be careful with types that hold secrets: a Password or APIKey type with func (APIKey) String() string { return "[redacted]" } stops keys leaking into logs. For structured production logging, prefer log/slog over Printf-style messages (Chapter 16).

unicode, text/template and regexp

The unicode package

The unicode package classifies runes: is it a letter, a digit, whitespace, upper case? It knows about every script, not just English, so use it instead of hand-written checks like r >= 'a' && r <= 'z'.

package main

import (
	"fmt"
	"unicode"
)

func main() {
	for _, r := range "aZ9 _é!\tΩ" {
		fmt.Printf("%q letter=%-5t digit=%-5t space=%-5t upper=%-5t punct=%t\n",
			r, unicode.IsLetter(r), unicode.IsDigit(r), unicode.IsSpace(r),
			unicode.IsUpper(r), unicode.IsPunct(r))
	}
	fmt.Println(string(unicode.ToUpper('é')), string(unicode.ToLower('Ω')))
	fmt.Println(unicode.Is(unicode.Greek, 'Ω'), unicode.In('ж', unicode.Cyrillic, unicode.Latin))
}
  1. range over the string yields runes. Each one is run through five classifiers. %-5t pads the booleans so the columns line up.
  2. 'Z' is a letter and upper case.
  3. '9' is a digit, not a letter.
  4. A space is whitespace.
  5. Underscore counts as punctuation in Unicode, not as a letter. Watch out if you're validating identifiers.
  6. 'é' is a letter. A hand-written r >= 'a' && r <= 'z' check would have missed it.
  7. '!' is punctuation.
  8. A tab is whitespace too. %q shows it as an escape so it stays visible.
  9. Greek capital omega: a letter and upper case. The package knows every script.
  10. Case mapping works beyond ASCII too.
  11. unicode.Is tests one script table; unicode.In tests whether the rune is in any of several.

text/template, briefly

When you need to generate text with a fixed shape (emails, config files, code, reports), text/template separates the shape from the data. Actions inside {{ }} pull fields from the data (.Customer), loop (range), branch (if), and call functions. A - inside the braces ({{-) trims whitespace next to the action.

package main

import (
	"os"
	"strings"
	"text/template"
)

type Order struct {
	Customer string
	Items    []string
	Total    float64
	Paid     bool
}

const tmpl = `Hello {{.Customer | upper}},
You ordered {{len .Items}} item(s):
{{- range $i, $it := .Items}}
  {{$i}}. {{$it}}
{{- end}}
Total: ${{printf "%.2f" .Total}}
{{if .Paid}}Thanks for paying!{{else}}Payment pending.{{end}}
`

func main() {
	funcs := template.FuncMap{"upper": strings.ToUpper}
	t := template.Must(template.New("order").Funcs(funcs).Parse(tmpl))
	o := Order{Customer: "ann", Items: []string{"book", "pen"}, Total: 23.5}
	if err := t.Execute(os.Stdout, o); err != nil {
		panic(err)
	}
}

Gotcha: HTML needs html/template

For anything that ends up in a web page, use html/template instead. It has the same API but automatically escapes values based on context, preventing cross-site scripting (XSS) attacks. text/template does no escaping at all.

regexp basics

The regexp package implements regular expressions using Google's RE2 syntax. RE2 guarantees matching in time linear in the input size, so a malicious pattern or input can't hang your server (a real risk in some other languages' regex engines). The trade-off is that it doesn't support backreferences or lookarounds.

package main

import (
	"fmt"
	"regexp"
)

// Compile once, at package level. MustCompile panics on a bad pattern.
var (
	emailRe = regexp.MustCompile(`^[\w.+-]+@[\w-]+\.[\w.]+$`)
	dateRe  = regexp.MustCompile(`(\d{4})-(\d{2})-(\d{2})`)
	kvRe    = regexp.MustCompile(`(?P<key>\w+)=(?P<val>\w+)`)
)

func main() {
	fmt.Println(emailRe.MatchString("ann@example.com"), emailRe.MatchString("not-an-email"))

	log := "deploys on 2024-03-01 and 2025-12-24"
	fmt.Println(dateRe.FindString(log))
	fmt.Println(dateRe.FindAllString(log, -1))

	m := dateRe.FindStringSubmatch(log)
	fmt.Println("year:", m[1], "month:", m[2], "day:", m[3])

	// Rewrite using capture groups: $1, $2 ...
	fmt.Println(dateRe.ReplaceAllString(log, "$3/$2/$1"))

	// Named groups
	sm := kvRe.FindStringSubmatch("user=ann")
	fmt.Println(sm[kvRe.SubexpIndex("key")], "->", sm[kvRe.SubexpIndex("val")])

	// Bad patterns return an error from Compile.
	_, err := regexp.Compile(`a(b`)
	fmt.Println(err)
}
  1. Before main runs, the package-level vars are initialised: each pattern is compiled exactly once. A typo here would panic at start-up, not in the middle of a request.
  2. ^ and $ anchor the pattern to the whole string. The first input matches; "not-an-email" has no @.
  3. FindString returns only the first match.
  4. FindAllString with -1 means "no limit": every match.
  5. FindStringSubmatch returns the full match at index 0, then one entry per capture group ( ).
  6. ReplaceAllString rewrites every match; $1, $2, $3 refer to the captured groups, so we can reorder the date parts.
  7. Named groups (?P<key>...) let you look up a group's index by name instead of counting parentheses.
  8. For patterns that come from users, use regexp.Compile, which returns an error instead of panicking.

  • Compile once. Compiling a pattern is expensive. Store it in a package-level var with MustCompile (which panics on a bad pattern, so you find out at start-up), not inside a function that runs per request.
  • A compiled *regexp.Regexp is safe for concurrent use by many goroutines.
  • Method names follow a pattern: Find / FindAll, plus String (string input), Submatch (capture groups), Index (positions).

Reach for the strings package first. strings.HasPrefix, Contains and Cut are clearer and dramatically faster than an equivalent regex. Use regexp when the pattern is genuinely a pattern (varying digits, optional parts, alternatives), and for validation keep in mind that real-world email or URL validation is better done with net/mail or net/url.

Putting it together: a word-frequency counter

Let's combine everything into a small but realistic program: count how often each word appears in a text, ignoring case and punctuation, and print the top five with a little bar chart. It uses bufio.Scanner to split into words, unicode to trim punctuation, a map to count, and slices.SortFunc to rank.

The core idea is a map from word to count. Here it is in miniature first:

counts := map[string]int{}
for _, w := range strings.Fields("the cat the hat") {
	counts[w]++
}
fmt.Println(counts, len(counts))
  1. An empty map. Any missing key reads as 0.
  2. Fields gives ["the" "cat" "the" "hat"]. First word: counts["the"] was 0, ++ makes it 1.
  3. "cat" is new: 0 → 1.
  4. "the" again: the existing 1 becomes 2. No "if it exists" check needed.
  5. "hat" is new: 0 → 1.
  6. Three distinct words. fmt prints map keys sorted, so the output is stable.

And the full program:

package main

import (
	"bufio"
	"cmp"
	"fmt"
	"maps"
	"slices"
	"strings"
	"unicode"
)

const text = `Go is expressive, concise, clean, and efficient. Its concurrency
mechanisms make it easy to write programs that get the most out of multicore
and networked machines. Go compiles quickly to machine code yet has the
convenience of garbage collection. Go is fast; go is fun! It's "Go".`

type wordCount struct {
	word  string
	count int
}

func countWords(input string) map[string]int {
	counts := make(map[string]int)
	sc := bufio.NewScanner(strings.NewReader(input))
	sc.Split(bufio.ScanWords) // split on whitespace
	for sc.Scan() {
		// Trim punctuation from both ends, keep inner apostrophes.
		w := strings.TrimFunc(sc.Text(), func(r rune) bool {
			return !unicode.IsLetter(r) && !unicode.IsNumber(r)
		})
		if w == "" {
			continue
		}
		counts[strings.ToLower(w)]++
	}
	return counts
}

func topN(counts map[string]int, n int) []wordCount {
	list := make([]wordCount, 0, len(counts))
	for w, c := range counts {
		list = append(list, wordCount{w, c})
	}
	slices.SortFunc(list, func(a, b wordCount) int {
		return cmp.Or(cmp.Compare(b.count, a.count), cmp.Compare(a.word, b.word))
	})
	return list[:min(n, len(list))]
}

func main() {
	counts := countWords(text)
	fmt.Println("distinct words:", len(counts))
	for i, wc := range topN(counts, 5) {
		bar := strings.Repeat("█", wc.count)
		fmt.Printf("%d. %-6s %2d %s\n", i+1, wc.word, wc.count, bar)
	}
	fmt.Println("first alphabetically:", slices.Sorted(maps.Keys(counts))[:3])
}
distinct words: 37
1. go      5 █████
2. is      3 ███
3. and     2 ██
4. of      2 ██
5. the     2 ██
first alphabetically: [and clean code]

Some details worth pointing out:

  • bufio.Scanner with ScanWords reads from any io.Reader, so the same function would work on a huge file or a network stream without loading it all into memory.
  • strings.TrimFunc removes punctuation only from the ends, so "It's" keeps its apostrophe while "Go". becomes Go.
  • Lowercasing before counting makes "Go" and "go" the same word.
  • The sort uses cmp.Or to rank by count descending and break ties alphabetically, so the output is deterministic even though map iteration isn't.
  • min(n, len(list)) uses the built-in min (Go 1.21) to avoid slicing past the end.

Exercise 2: a Unicode-aware palindrome checker

Write IsPalindrome(s string) bool that ignores case, spaces and punctuation. "A man, a plan, a canal: Panama!" should be true. Hint: range over the string, keep only letters and digits (lower-cased) in a []rune, then compare from both ends.

package main

import (
	"fmt"
	"unicode"
)

// IsPalindrome ignores case, spaces and punctuation.
func IsPalindrome(s string) bool {
	var rs []rune
	for _, r := range s {
		if unicode.IsLetter(r) || unicode.IsDigit(r) {
			rs = append(rs, unicode.ToLower(r))
		}
	}
	for i, j := 0, len(rs)-1; i < j; i, j = i+1, j-1 {
		if rs[i] != rs[j] {
			return false
		}
	}
	return true
}

func main() {
	for _, s := range []string{"A man, a plan, a canal: Panama!", "Go hang a salami, I'm a lasagna hog.", "gopher"} {
		fmt.Printf("%-40q %t\n", s, IsPalindrome(s))
	}

Exercise 3: parse a query string

Write ParseQuery(q string) map[string]string that turns "name=ann&age=31&debug" into a map. A key with no = maps to an empty string; skip empty pairs; trim spaces. Hint: strings.SplitSeq for the pairs, strings.Cut for each one. (In real code, use net/url.ParseQuery, which also handles percent-encoding.)

Solution
package main

import (
	"fmt"
	"strings"
)

// ParseQuery parses "a=1&b=two&flag" into a map. Keys without "=" map to "".
func ParseQuery(q string) map[string]string {
	out := make(map[string]string)
	for pair := range strings.SplitSeq(q, "&") {
		if pair == "" {
			continue
		}
		k, v, _ := strings.Cut(pair, "=")
		out[strings.TrimSpace(k)] = strings.TrimSpace(v)
	}
	return out
}

func main() {
	fmt.Println(ParseQuery("name=ann&age=31&debug&&x = y "))
}

Key takeaways

  • A Go string is an immutable sequence of bytes, conventionally UTF-8. Copying and slicing strings is cheap because bytes are shared.
  • len(s) counts bytes; utf8.RuneCountInString(s) counts runes. Indexing s[i] gives a byte; for i, r := range s gives runes and byte offsets.
  • byte = uint8, rune = int32 (a code point). Convert to []rune for character-level work, []byte for mutation or I/O.
  • string(65) is "A"; use strconv.Itoa for numbers. Let go vet catch it.
  • Learn the strings package: Cut, Fields, TrimSpace, EqualFold, HasPrefix and Builder cover most needs.
  • += in a loop is quadratic; use strings.Builder (with Grow if you know the size), or write straight to an io.Writer.
  • strconv converts text to numbers strictly and with good errors; always check them.
  • Know the core fmt verbs (%v %+v %#v %T %q %x %d %s %f) and the [flags][width][.precision] shape; go vet checks format strings.
  • Use html/template for HTML, compile regexps once, and prefer plain strings functions over regex when they suffice.
