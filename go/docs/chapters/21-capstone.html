What we're building

A small but real JSON API for to-do items. Think of the backend for a Trello-style board. Here's the full contract:

Method & pathDoesSuccessErrors
GET /healthzLiveness check200
POST /tasksCreate a task from {"title", "description", "due"}201 + Location400 bad JSON, 422 invalid fields

Plus two behaviours that make it more than CRUD (Create, Read, Update, Delete):

  • A background worker wakes up on a timer and flags tasks whose due time has passed as "overdue": true.
  • Graceful shutdown: on Ctrl-C or SIGTERM, the server finishes in-flight requests and the worker stops cleanly before the process exits.

We'll use only the standard library. No web framework, no router library, no logging library. Go 1.22's ServeMux and log/slog cover everything a service like this needs.

The rules behind this shape come straight from Chapter 19:

Mental model

Think of a restaurant. The HTTP layer is the waiter: takes the order in the customer's language (JSON), checks it's legible, and brings back the plate. The service is the head chef: knows the recipes and rules ("we don't serve tasks without a title"). The store is the pantry: just keeps things safely. The waiter never cooks, and the chef never talks to customers. That's why we can swap the pantry (memory → Postgres) or add a second waiter (gRPC) without retraining the chef.

The domain: types, errors and the Store contract

We start from the inside, with the package that describes the problem rather than the technology. It knows what a task is and what errors can happen, and it says what it needs from storage. It knows nothing about HTTP, JSON transport or databases.

// Package task is the domain core of the Task API: what a task is,
// the rules about it, and the storage contract. It imports nothing
// else from this module.
package task

import (
	"errors"
	"fmt"
	"time"
)

// Status is where a task is in its life cycle.
type Status string

const (
	StatusTodo  Status = "todo"
	StatusDoing Status = "doing"
	StatusDone  Status = "done"
)

// Valid reports whether s is a known status.
func (s Status) Valid() bool {
	switch s {
	case StatusTodo, StatusDoing, StatusDone:
		return true
	}
	return false
}

// Task is a single to-do item.
type Task struct {
	ID          string     `json:"id"`
	Title       string     `json:"title"`
	Description string     `json:"description,omitempty"`
	Status      Status     `json:"status"`
	Due         *time.Time `json:"due,omitempty"`
	Overdue     bool       `json:"overdue"`
	CreatedAt   time.Time  `json:"created_at"`
	UpdatedAt   time.Time  `json:"updated_at"`
}

// ErrNotFound is returned when a task does not exist.
var ErrNotFound = errors.New("task not found")

// ErrValidation is the category of every *ValidationError,
// so callers can test errors.Is(err, ErrValidation).
var ErrValidation = errors.New("validation failed")

// ValidationError describes one invalid input field.
type ValidationError struct {
	Field string
	Msg   string
}

func (e *ValidationError) Error() string { return fmt.Sprintf("%s: %s", e.Field, e.Msg) }

// Unwrap makes errors.Is(err, ErrValidation) true for every ValidationError.
func (e *ValidationError) Unwrap() error { return ErrValidation }

Design decisions worth pointing out:

  • Status is a named string type with constants, an "enum" in Go style, plus a Valid method so validation lives next to the type.
  • Due is a *time.Time because "no due date" is a real state, and a nil pointer models it honestly (and omitempty drops it from JSON).
  • Two kinds of errors: a sentinel ErrNotFound for "this thing doesn't exist", and a typed *ValidationError that carries the field name. Its Unwrap method returns ErrValidation, so callers can choose: errors.Is(err, ErrValidation) for the category, or errors.As(err, &ve) for the details.

Next, the contract any storage must fulfil. The interface lives here, in the package that uses it ("accept interfaces"), not in the store package:

package task

import "context"

// Filter narrows a List call. The zero Filter matches every task.
type Filter struct {
	Status Status // "" means any status
}

// Store persists tasks. Implementations must be safe for concurrent use
// and must return ErrNotFound for unknown IDs.
type Store interface {
	Create(ctx context.Context, t Task) error
	Get(ctx context.Context, id string) (Task, error)
	List(ctx context.Context, f Filter) ([]Task, error)
	Update(ctx context.Context, t Task) error
	Delete(ctx context.Context, id string) error
}

Every method takes context.Context first, even though our memory store barely needs it. A real database driver uses it to cancel queries when the client disconnects or a deadline passes. Putting it in the interface from day one means switching to Postgres later changes no signatures.

The service layer: business rules and validation

The service is where the rules live: titles are required and trimmed, due dates must be in the future, finished tasks are never overdue, new tasks start as todo. It depends only on the Store interface. Two small seams make it testable: now (the clock) and newID (ID generation) are function fields, so tests can control time.

package task

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"strings"
	"time"
	"unicode/utf8"
)

const maxTitleLen = 200

// Service holds the business rules. It is safe for concurrent use
// as long as its Store is.
type Service struct {
	store Store
	now   func() time.Time // swapped in tests for a fixed clock
	newID func() string
}

// NewService returns a Service backed by store.
func NewService(store Store) *Service {
	return &Service{store: store, now: time.Now, newID: randomID}
}

func randomID() string {
	b := make([]byte, 6)
	rand.Read(b) // crypto/rand.Read never returns an error since Go 1.24
	return hex.EncodeToString(b)
}

// CreateInput is what a caller may set when creating a task.
type CreateInput struct {
	Title       string
	Description string
	Due         *time.Time
}

// Create validates in and stores a new task with status "todo".
func (s *Service) Create(ctx context.Context, in CreateInput) (Task, error) {
	title, err := validTitle(in.Title)
	if err != nil {
		return Task{}, err
	}
	now := s.now().UTC()
	if in.Due != nil && in.Due.Before(now) {
		return Task{}, &ValidationError{Field: "due", Msg: "must be in the future"}
	}
	t := Task{
		ID:          s.newID(),
		Title:       title,
		Description: strings.TrimSpace(in.Description),
		Status:      StatusTodo,
		Due:         utcPtr(in.Due),
		CreatedAt:   now,
		UpdatedAt:   now,
	}
	if err := s.store.Create(ctx, t); err != nil {
		return Task{}, fmt.Errorf("create task: %w", err)
	}
	return t, nil
}

// Get returns one task by ID.
func (s *Service) Get(ctx context.Context, id string) (Task, error) {
	t, err := s.store.Get(ctx, id)
	if err != nil {
		return Task{}, fmt.Errorf("get task %s: %w", id, err)
	}
	return t, nil
}

// List returns tasks matching f, oldest first.
func (s *Service) List(ctx context.Context, f Filter) ([]Task, error) {
	if f.Status != "" && !f.Status.Valid() {
		return nil, &ValidationError{Field: "status", Msg: "must be todo, doing or done"}
	}
	ts, err := s.store.List(ctx, f)
	if err != nil {
		return nil, fmt.Errorf("list tasks: %w", err)
	}
	return ts, nil
}

// UpdateInput is a partial update: nil fields are left unchanged.
type UpdateInput struct {
	Title       *string
	Description *string
	Status      *Status
	Due         *time.Time
}

// Update applies in to the task with the given ID.
func (s *Service) Update(ctx context.Context, id string, in UpdateInput) (Task, error) {
	t, err := s.store.Get(ctx, id)
	if err != nil {
		return Task{}, fmt.Errorf("update task %s: %w", id, err)
	}
	if in.Title != nil {
		if t.Title, err = validTitle(*in.Title); err != nil {
			return Task{}, err
		}
	}
	if in.Description != nil {
		t.Description = strings.TrimSpace(*in.Description)
	}
	if in.Status != nil {
		if !in.Status.Valid() {
			return Task{}, &ValidationError{Field: "status", Msg: "must be todo, doing or done"}
		}
		t.Status = *in.Status
	}
	if in.Due != nil {
		t.Due = utcPtr(in.Due)
		t.Overdue = false // a new deadline resets the flag
	}
	if t.Status == StatusDone {
		t.Overdue = false // finished work is never overdue
	}
	t.UpdatedAt = s.now().UTC()
	if err := s.store.Update(ctx, t); err != nil {
		return Task{}, fmt.Errorf("update task %s: %w", id, err)
	}
	return t, nil
}

// Delete removes a task.
func (s *Service) Delete(ctx context.Context, id string) error {
	if err := s.store.Delete(ctx, id); err != nil {
		return fmt.Errorf("delete task %s: %w", id, err)
	}
	return nil
}

// MarkOverdue flags every unfinished task whose due time has passed.
// It returns how many tasks it changed.
func (s *Service) MarkOverdue(ctx context.Context) (int, error) {
	ts, err := s.store.List(ctx, Filter{})
	if err != nil {
		return 0, fmt.Errorf("mark overdue: %w", err)
	}
	now := s.now().UTC()
	changed := 0
	for _, t := range ts {
		if t.Status == StatusDone || t.Overdue || t.Due == nil || !t.Due.Before(now) {
			continue
		}
		t.Overdue = true
		t.UpdatedAt = now
		if err := s.store.Update(ctx, t); err != nil {
			return changed, fmt.Errorf("mark overdue %s: %w", t.ID, err)
		}
		changed++
	}
	return changed, nil
}

func validTitle(title string) (string, error) {
	title = strings.TrimSpace(title)
	switch {
	case title == "":
		return "", &ValidationError{Field: "title", Msg: "is required"}
	case utf8.RuneCountInString(title) > maxTitleLen:
		return "", &ValidationError{Field: "title", Msg: fmt.Sprintf("must be at most %d characters", maxTitleLen)}
	}
	return title, nil
}

func utcPtr(t *time.Time) *time.Time {
	if t == nil {
		return nil
	}
	u := t.UTC()
	return &u
}
func (s *Service) Create(ctx context.Context, in CreateInput) (Task, error) {
	title, err := validTitle(in.Title)
	if err != nil {
		return Task{}, err
	}
	now := s.now().UTC()
	if in.Due != nil && in.Due.Before(now) {
		return Task{}, &ValidationError{Field: "due", Msg: "must be in the future"}
	}
	t := Task{
		ID:          s.newID(),
		Title:       title,
		Description: strings.TrimSpace(in.Description),
		Status:      StatusTodo,
		Due:         utcPtr(in.Due),
		CreatedAt:   now,
		UpdatedAt:   now,
	}
	if err := s.store.Create(ctx, t); err != nil {
		return Task{}, fmt.Errorf("create task: %w", err)
	}
	return t, nil
}
  1. The handler calls Create with a title of three spaces, like our curl request below does.
  2. First rule: validTitle trims the spaces. The result is empty, so it returns &ValidationError{Field: "title", Msg: "is required"}.
  3. We return immediately with the zero Task{} and that error, unwrapped. Validation errors are already self-explanatory, so no extra context is added. Nothing touched the store.
  4. On a valid request, we'd read the clock once (so CreatedAt and UpdatedAt are identical) and check that the due date isn't in the past.
  5. Then build the Task: a fresh random ID, trimmed fields, status todo, due date normalised to UTC.
  6. Then save it. A store failure gets wrapped with %w and context ("create task: ..."), so errors.Is still works upstream.
  7. Back in the HTTP layer, fail sees errors.As(err, &ve) succeed and responds 422 with the field name, exactly as the curl session shows.

Notice what the service doesn't do: it never mentions HTTP status codes. "Not found" and "invalid title" are domain facts; 404 and 422 are HTTP's way of saying them. Keeping that translation in exactly one place (httpapi.fail) means a future gRPC adapter can map the same errors to codes.NotFound and codes.InvalidArgument without touching the service.

A test-only door for the clock

Our tests live in package task_test (an "external" test package) so they use the API exactly like real callers do. But they need to inject a fixed clock, and now is unexported. The idiomatic trick is an export_test.go file: it's in package task, so it can touch private fields, but because its name ends in _test.go it is only compiled during go test. It never ships.

package task

import "time"

// NewServiceForTest lets external tests (package task_test) inject a clock.
// Files ending in _test.go are only compiled by `go test`, so this
// helper never ships in the real binary.
func NewServiceForTest(store Store, now func() time.Time) *Service {
	s := NewService(store)
	s.now = now
	return s
}

The memory store: a map behind an RWMutex

Now the outer layer that holds data. Many HTTP requests run at the same time, each in its own goroutine, so the map must be protected. A sync.RWMutex allows many readers at once (RLock) or one writer alone (Lock). That suits an API where reads (list, get) are far more common than writes.

// Package memstore is an in-memory task.Store, safe for concurrent use.
// It is perfect for tests and demos; swap in a database for production.
package memstore

import (
	"cmp"
	"context"
	"fmt"
	"slices"
	"sync"

	"example.com/taskapi/internal/task"
)

// Store keeps tasks in a map guarded by a read/write mutex.
// The zero value is not usable; call New.
type Store struct {
	mu    sync.RWMutex // guards tasks
	tasks map[string]task.Task
}

// New returns an empty Store.
func New() *Store {
	return &Store{tasks: make(map[string]task.Task)}
}

// Compile-time proof that *Store satisfies task.Store.
var _ task.Store = (*Store)(nil)

func (s *Store) Create(ctx context.Context, t task.Task) error {
	if err := ctx.Err(); err != nil {
		return err
	}
	s.mu.Lock()
	defer s.mu.Unlock()
	if _, exists := s.tasks[t.ID]; exists {
		return fmt.Errorf("memstore: duplicate id %q", t.ID)
	}
	s.tasks[t.ID] = t
	return nil
}

func (s *Store) Get(ctx context.Context, id string) (task.Task, error) {
	if err := ctx.Err(); err != nil {
		return task.Task{}, err
	}
	s.mu.RLock()
	defer s.mu.RUnlock()
	t, ok := s.tasks[id]
	if !ok {
		return task.Task{}, task.ErrNotFound
	}
	return t, nil
}

func (s *Store) List(ctx context.Context, f task.Filter) ([]task.Task, error) {
	if err := ctx.Err(); err != nil {
		return nil, err
	}
	s.mu.RLock()
	out := make([]task.Task, 0, len(s.tasks)) // never nil: JSON gets [] not null
	for _, t := range s.tasks {
		if f.Status == "" || t.Status == f.Status {
			out = append(out, t)
		}
	}
	s.mu.RUnlock()

	// Map order is random; sort for a stable API (oldest first, then by ID).
	slices.SortFunc(out, func(a, b task.Task) int {
		return cmp.Or(a.CreatedAt.Compare(b.CreatedAt), cmp.Compare(a.ID, b.ID))
	})
	return out, nil
}

func (s *Store) Update(ctx context.Context, t task.Task) error {
	if err := ctx.Err(); err != nil {
		return err
	}
	s.mu.Lock()
	defer s.mu.Unlock()
	if _, ok := s.tasks[t.ID]; !ok {
		return task.ErrNotFound
	}
	s.tasks[t.ID] = t
	return nil
}

func (s *Store) Delete(ctx context.Context, id string) error {
	if err := ctx.Err(); err != nil {
		return err
	}
	s.mu.Lock()
	defer s.mu.Unlock()
	if _, ok := s.tasks[id]; !ok {
		return task.ErrNotFound
	}
	delete(s.tasks, id)
	return nil
}
  • var _ task.Store = (*Store)(nil) is a compile-time assertion: if we ever break the interface, the build fails right here with a clear message, instead of somewhere in main.
  • The map stores task.Task values, not pointers. Get returns a copy, so a caller modifying its task can't change the stored one behind the lock's back. (The Due pointer is shared, but nobody mutates a time.Time through it; we always replace the pointer.)
  • List releases the read lock before sorting. Hold locks for the shortest time possible: copy out, unlock, then do the slow work.
  • make([]task.Task, 0, n) rather than var out []task.Task, so an empty list encodes as [] instead of null (gotcha #18).
  • Sorting with cmp.Or gives a stable order: by creation time, and by ID as a tie-breaker. Without it, map iteration order would make every list response random (gotcha #10).
Gotcha

defer s.mu.RUnlock() is the safe default and is used everywhere else. In List we unlock manually to release the lock early. That's fine for a short block with no early returns, but if you add a return inside that block later, you'll leak the lock and the whole API will freeze on the next write. If in doubt, move the locked part into its own small function with a defer.

List is where the memstore earns its keep: a filtered copy under a read lock, then a sort, because map order is random. The store holds two tasks at this point: "Write the capstone" (doing) and "Pay invoice" (todo).

// internal/memstore/memstore.go
func (s *Store) List(ctx context.Context, f task.Filter) ([]task.Task, error) {
	if err := ctx.Err(); err != nil {
		return nil, err
	}
	s.mu.RLock()
	out := make([]task.Task, 0, len(s.tasks)) // never nil: JSON gets [] not null
	for _, t := range s.tasks {
		if f.Status == "" || t.Status == f.Status {
			out = append(out, t)
		}
	}
	s.mu.RUnlock()

	// Map order is random; sort for a stable API (oldest first, then by ID).
	slices.SortFunc(out, func(a, b task.Task) int {
		return cmp.Or(a.CreatedAt.Compare(b.CreatedAt), cmp.Compare(a.ID, b.ID))
	})
	return out, nil
}
  1. The service already validated status=doing. The store checks for a cancelled context first.
  2. Read-lock, then allocate the result with capacity for every task. make(..., 0, n) is never nil, so an empty result encodes as [], not null.
  3. The range visits tasks in random order. The doing task matches the filter and is appended. Appending a struct copies it, so callers can't modify the store's data.
  4. The todo task does not match and is skipped.
  5. Unlock before sorting: the sort only touches our private copy, so there's no reason to keep writers waiting.
  6. Sort oldest first; cmp.Or uses the ID as a tie-breaker so the order is fully deterministic. The handler wraps it as {tasks, count}.

The HTTP layer: routing, JSON and error mapping

This package turns HTTP requests into service calls and service results into HTTP responses. It uses the Go 1.22+ ServeMux patterns: "GET /tasks/{id}" matches only GET (and HEAD), and r.PathValue("id") reads the wildcard. Wrong methods get an automatic 405 Method Not Allowed with an Allow header.

// Package httpapi exposes the task service over HTTP and JSON.
package httpapi

import (
	"encoding/json"
	"errors"
	"fmt"
	"log/slog"
	"net/http"
	"time"

	"example.com/taskapi/internal/task"
)

const maxBodyBytes = 1 << 20 // 1 MiB

// API holds the dependencies every handler needs.
type API struct {
	svc *task.Service
	log *slog.Logger
}

// New returns the fully wired HTTP handler: routes plus middleware.
func New(svc *task.Service, log *slog.Logger) http.Handler {
	a := &API{svc: svc, log: log}

	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", a.health)
	mux.HandleFunc("POST /tasks", a.createTask)
	mux.HandleFunc("GET /tasks", a.listTasks)
	mux.HandleFunc("GET /tasks/{id}", a.getTask)
	mux.HandleFunc("PATCH /tasks/{id}", a.updateTask)
	mux.HandleFunc("DELETE /tasks/{id}", a.deleteTask)

Middleware: recover, request IDs, logging

Middleware is a function that takes a handler and returns a new handler that does something before and/or after calling the original. It's how we add cross-cutting behaviour to every route without touching any handler.

// chain applies mws so that the first one listed is the outermost.
func chain(h http.Handler, mws ...middleware) http.Handler {
	for i := len(mws) - 1; i >= 0; i-- {
		h = mws[i](h)
	}
	return h
}

type ctxKey struct{} // unexported type: no other package can collide with it

// RequestIDFrom returns the request ID stored by the requestID middleware.
func RequestIDFrom(ctx context.Context) string {
	id, _ := ctx.Value(ctxKey{}).(string)
	return id
}

// requestID reuses an incoming X-Request-ID or creates one, stores it in
// the context, and echoes it in the response.
func requestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" || len(id) > 64 {
			b := make([]byte, 8)
			rand.Read(b)
			id = hex.EncodeToString(b)
		}
		w.Header().Set("X-Request-ID", id)
		ctx := context.WithValue(r.Context(), ctxKey{}, id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

// recoverPanics turns a panicking handler into a 500 instead of a dropped connection.
func (a *API) recoverPanics(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if v := recover(); v != nil {
				if v == http.ErrAbortHandler { // deliberate abort: let net/http handle it
					panic(v)
				}
				a.log.ErrorContext(r.Context(), "panic", "value", v, "stack", string(debug.Stack()))
				writeJSON(w, http.StatusInternalServerError, errorBody{Error: "internal error"})
			}
		}()
		next.ServeHTTP(w, r)
	})
}

  2. So we loop backwards. First we wrap the mux in the logger, the innermost layer.
  3. Then wrap that in requestID. Because it's outside the logger, the ID is already in the context when the log line is written.

The background worker and main

A ticker plus a context

The worker is a loop that waits for one of two things: a tick (do the work) or a cancelled context (stop). It accepts a one-method interface, Marker, instead of *task.Service, which makes it trivially testable with a fake.

// Overdue periodically flags tasks whose due time has passed.
type Overdue struct {

	Interval time.Duration
	Log      *slog.Logger

// Run blocks, ticking every Interval, until ctx is cancelled.
func (w *Overdue) Run(ctx context.Context) {
	w.Log.Info("overdue worker started", "interval", w.Interval.String())
	t := time.NewTicker(w.Interval)
	defer t.Stop()
	for {
		select {
		case <-ctx.Done():
			w.Log.Info("overdue worker stopped")
			return
		case <-t.C:
			w.tick(ctx)
		}
	}
}

	case err != nil:

	case n > 0:

// internal/task/service.go
func (s *Service) MarkOverdue(ctx context.Context) (int, error) {
	ts, err := s.store.List(ctx, Filter{})
	if err != nil {
		return 0, fmt.Errorf("mark overdue: %w", err)
	}
	now := s.now().UTC()
	changed := 0
	for _, t := range ts {
		if t.Status == StatusDone || t.Overdue || t.Due == nil || !t.Due.Before(now) {
			continue
		}
		t.Overdue = true
		t.UpdatedAt = now
		if err := s.store.Update(ctx, t); err != nil {
			return changed, fmt.Errorf("mark overdue %s: %w", t.ID, err)
		}
		changed++
	}
	return changed, nil
}

  4. The capstone task has no due date: t.Due == nil, so we continue. (The order of checks matters: t.Due.Before would panic on nil.)
  5. Status todo, not yet overdue, has a due date, and 18:17:46 is before now. All checks pass.
  6. Set the flag on our copy and write it back with store.Update.
  7. Count it and return 1. A task already flagged is skipped next time, so the job is idempotent.
  8. Back in tick: no error and n > 0, so we log once. Ticks that change nothing stay silent; that keeps the logs useful.

		if err != nil || d <= 0 {
			return c, fmt.Errorf("OVERDUE_INTERVAL: invalid duration %q", v)
		}
		c.overdueInterval = d
	}
	if v := os.Getenv("LOG_LEVEL"); v != "" {
		if err := c.logLevel.UnmarshalText([]byte(v)); err != nil {
			return c, fmt.Errorf("LOG_LEVEL: %w", err)
		}
	}
	return c, nil
}

func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, "error:", err)
		os.Exit(1)
	}
}

func run() error {
	cfg, err := loadConfig()
	if err != nil {
		return err
	}
	log := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: cfg.logLevel}))
	log = log.With("app", "taskapi", "version", version)

	// ctx is cancelled on Ctrl-C or SIGTERM: the single "time to stop" signal.
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	// Wiring: the only place that knows every concrete type.
	store := memstore.New()
	svc := task.NewService(store)
	handler := httpapi.New(svc, log)

	var wg sync.WaitGroup
	overdue := &worker.Overdue{Marker: svc, Interval: cfg.overdueInterval, Log: log}
	wg.Go(func() { overdue.Run(ctx) })

	srv := &http.Server{
		Addr:              cfg.addr,
		Handler:           handler,
		ReadHeaderTimeout: 5 * time.Second,
		ReadTimeout:       15 * time.Second,
		WriteTimeout:      15 * time.Second,
		IdleTimeout:       60 * time.Second,
	}

	serveErr := make(chan error, 1)
	go func() {
		log.Info("listening", "addr", cfg.addr)
		serveErr <- srv.ListenAndServe()
	}()

	select {
	case err := <-serveErr:
		return fmt.Errorf("server: %w", err) // e.g. port already in use
	case <-ctx.Done():
		log.Info("shutting down")
	}

	shutdownCtx, cancel := context.WithTimeout(context.Background(), cfg.shutdownTimeout)
	defer cancel()
	if err := srv.Shutdown(shutdownCtx); err != nil && !errors.Is(err, http.ErrServerClosed) {
		return fmt.Errorf("shutdown: %w", err)
	}
	wg.Wait() // the worker saw ctx.Done() too; wait for it to return
	log.Info("stopped cleanly")
	return nil
}

The shutdown order is deliberate:

  1. The signal cancels ctx. The worker notices and begins stopping.
  2. srv.Shutdown stops accepting connections and waits (up to 10s) for in-flight requests to finish. Request contexts are not derived from ctx (the server's default base context is context.Background()), so in-flight requests aren't cancelled mid-way. They're allowed to finish, which is the whole point of draining.
  3. wg.Wait() makes sure the worker has fully returned.
  4. Only then does run return, and the process exits 0.

The serveErr channel has a buffer of 1. That's not an accident: after a normal shutdown, ListenAndServe returns ErrServerClosed and the goroutine sends it, but nobody is receiving any more. With an unbuffered channel that goroutine would block forever, a small goroutine leak (gotcha #17). The buffer gives it somewhere to put the value and exit.

Worker: fake time with testing/synctest

Testing code with tickers used to mean real sleeps: slow and flaky. testing/synctest (standard since Go 1.25) runs the test in a bubble with a fake clock. Time only advances when every goroutine in the bubble is blocked, so "sleep 3 minutes" finishes instantly, and the worker is guaranteed to have ticked exactly 3 times.

package worker

import (
	"context"
	"io"
	"log/slog"
	"sync/atomic"
	"testing"
	"testing/synctest"
	"time"
)

// fakeMarker counts calls instead of touching real tasks.
type fakeMarker struct{ calls atomic.Int32 }

func (f *fakeMarker) MarkOverdue(context.Context) (int, error) {
	f.calls.Add(1)
	return 1, nil
}

func TestOverdueRunsAndStops(t *testing.T) {
	// synctest runs the test in a "bubble" with a fake clock: time only
	// moves when every goroutine in the bubble is blocked, so a
	// 3-minute sleep finishes instantly and deterministically.
	synctest.Test(t, func(t *testing.T) {
		fake := &fakeMarker{}
		w := &Overdue{
			Marker:   fake,
			Interval: time.Minute,
			Log:      slog.New(slog.NewTextHandler(io.Discard, nil)),
		}
		ctx, cancel := context.WithCancel(t.Context())
		done := make(chan struct{})
		go func() {
			w.Run(ctx)
			close(done)
		}()

		time.Sleep(3*time.Minute + time.Second) // fake time: returns at once
		synctest.Wait()                         // let the worker finish its tick
		if n := fake.calls.Load(); n != 3 {
			t.Errorf("MarkOverdue called %d times, want 3", n)
		}

		cancel()
		<-done // Run must return after cancel: no goroutine leak
	})
}

Why does worker.Overdue take a Marker interface instead of a *task.Service?
"Accept interfaces": the worker declares exactly what it needs, one method. *task.Service satisfies it implicitly, and the test passes a 5-line fake that counts calls. Interface calls are actually a tiny bit slower, but that's irrelevant here.

Read the logs alongside the session and you can see every design decision paying off:

  • Every line has app and version, and every request line has a request_id that matches the X-Request-Id header the client got back. When a user reports a problem, that ID finds the exact log line.
  • The route field shows the matched pattern (PATCH /tasks/{id}), perfect for grouping metrics without exploding cardinality. For the 405, no route matched, so it's empty.
  • The worker logged nothing for ticks with no changes, then marked tasks overdue count=1 right after the due time. The next GET showed "overdue": true.
  • The client-supplied X-Request-ID: demo-42 was reused, so a request can be traced across services.
  • On SIGTERM: worker stopped, server drained, "stopped cleanly", exit code 0.

One inconsistency is visible in the session: the 405 response is text/plain (written by ServeMux itself), while all our own errors are JSON. Many APIs accept that. If you want JSON everywhere, register a catch-all mux.HandleFunc("/", ...) for 404s and wrap the mux to rewrite 405s, or add per-path fallback handlers.

// markDone is a shortcut for PATCH {"status":"done"}.
func (a *API) markDone(w http.ResponseWriter, r *http.Request) {
	done := task.StatusDone
	t, err := a.svc.Update(r.Context(), r.PathValue("id"), task.UpdateInput{Status: &done})
	if err != nil {
		a.fail(w, r, err)
		return
	}
	writeJSON(w, http.StatusOK, t)
}

Exercise 2: Simple limit/offset pagination in the memory store

Before going all the way to cursors, add Limit and Offset to task.Filter, apply them in memstore.List after sorting, and default Limit to 50 (max 100) in the service. Write a table-driven test.

Solution
package memstore

import "example.com/taskapi/internal/task"

// page returns at most limit tasks starting at offset, never panicking
// on out-of-range values. limit <= 0 means "no limit".
func page(ts []task.Task, offset, limit int) []task.Task {
	offset = max(0, min(offset, len(ts)))
	end := len(ts)
	if limit > 0 {
		end = min(offset+limit, len(ts))
	}
	return ts[offset:end:end] // full slice expression: callers can't append into our array
}

Key takeaways

  • Layout: thin cmd/api/main.go for wiring; internal/ packages by role; the domain imports nothing of ours.
  • Domain: named types with Valid methods, a sentinel ErrNotFound, a typed ValidationError that unwraps to ErrValidation, and a consumer-owned Store interface with ctx everywhere.
  • Store: a map behind sync.RWMutex, values not pointers, short critical sections, sorted results, [] not null.
  • HTTP: Go 1.22 method+path patterns, careful JSON decoding (size limit, unknown fields), and a single fail function that maps domain errors to status codes.
  • Middleware composes like an onion: recover → request ID → logging → mux.
  • Concurrency: a ticker + context worker, a buffered error channel, wg.Go + wg.Wait, and an ordered graceful shutdown.
  • Tests match their layer: table-driven with a fake clock, -race for the store, httptest for handlers, synctest for time. And check that they fail when the code is broken.
  • The architecture's payoff is that features like Postgres, auth and pagination each land in one layer, in one reviewable PR.
