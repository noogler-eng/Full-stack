net/http basics: your first server

HTTP is a request/response protocol. A client sends a request (a method like GET or POST, a path like /tasks/1, headers, and maybe a body). The server sends back a response (a status code like 200, headers, and a body). A Go web server is a program that listens on a TCP port, parses each request, and calls your code to produce the response.

The smallest useful server is about ten lines:

package main

import (
	"fmt"
	"log"
	"net/http"
)

func main() {
	http.HandleFunc("/hello", func(w http.ResponseWriter, r *http.Request) {
		name := r.URL.Query().Get("name")
		if name == "" {
			name = "world"
		}
		fmt.Fprintf(w, "hello, %s! you sent %s %s\n", name, r.Method, r.URL.Path)
	})

	log.Println("listening on :8081")
	log.Fatal(http.ListenAndServe(":8081", nil)) // nil = use http.DefaultServeMux
}

What just happened:

  • http.HandleFunc registered a function for the path /hello on the default mux (a global router).
  • http.ListenAndServe(":8081", nil) started listening on port 8081 on all interfaces. It blocks forever, and only returns if something goes wrong.
  • For every connection, the server starts a new goroutine. So your handler runs concurrently with itself. That's how Go servers handle thousands of requests at once without you writing any concurrency code, and also why any shared state in handlers must be protected.
  • Unknown paths get a plain-text 404 page not found for free.
Gotcha

This "hello" version is fine for learning but has two production problems we'll fix later: it uses the global DefaultServeMux (any imported package can register routes on it, including net/http/pprof's debug endpoints), and http.ListenAndServe has no timeouts.

The Handler interface and HandlerFunc

Everything in net/http revolves around one interface:

type Handler interface {
	ServeHTTP(w ResponseWriter, r *Request)
}

// HandlerFunc lets an ordinary function act as a Handler.
type HandlerFunc func(ResponseWriter, *Request)

func (f HandlerFunc) ServeHTTP(w ResponseWriter, r *Request) {
	f(w, r) // just call the function itself
}

A Handler is anything that can answer a request. The two parameters are:

  • *http.Request: everything about the incoming request. r.Method, r.URL.Path, r.URL.Query(), r.Header, r.Body (an io.ReadCloser), and r.Context(), which is cancelled when the client disconnects.
  • http.ResponseWriter: how you build the response. Set headers with w.Header().Set(...), then the status with w.WriteHeader(code), then the body with w.Write(...) (it's an io.Writer, so fmt.Fprintf and json.NewEncoder(w) work).

HandlerFunc is a clever adapter: it's a function type with a ServeHTTP method that calls the function. Converting your function with http.HandlerFunc(myFunc) turns it into a Handler. mux.HandleFunc does that conversion for you.

package main

import (
	"fmt"
	"log"
	"net/http"
	"sync/atomic"
)

// counter is a Handler because it has a ServeHTTP method.
type counter struct {
	hits atomic.Int64 // handlers run concurrently: use atomics or locks
}

func (c *counter) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	n := c.hits.Add(1)
	fmt.Fprintf(w, "visit #%d\n", n)
}

func health(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusOK) // headers must be set BEFORE this
	w.Write([]byte(`{"status":"ok"}` + "\n"))
}

func main() {
	mux := http.NewServeMux()
	mux.Handle("/count", &counter{})                // a value implementing Handler
	mux.Handle("/health", http.HandlerFunc(health)) // a function converted to Handler
	mux.HandleFunc("/health2", health)              // shorthand for the line above

	log.Fatal(http.ListenAndServe(":8082", mux))
}

Mental model

A Handler is a function with a fixed shape: request in, response out. A router is a Handler that picks another Handler. Middleware is a Handler that wraps another Handler. The server is just a loop that calls the top Handler for each request. Once this clicks, all of net/http becomes "Handlers all the way down".

The order of ResponseWriter calls matters

The response is streamed to the client. The first call to Write sends the status line and headers immediately (with 200 OK if you didn't call WriteHeader). After that, changing the status or headers is impossible:

package main

import (
	"log"
	"net/http"
)

func main() {
	http.HandleFunc("/broken", func(w http.ResponseWriter, r *http.Request) {
		w.Write([]byte("oops, something failed\n"))   // implicitly sends 200 OK
		w.WriteHeader(http.StatusInternalServerError) // too late!
		w.Header().Set("X-Debug", "never sent")       // also too late
	})
	log.Fatal(http.ListenAndServe(":8084", nil))
}

Remember it as headers → status → body. Go warns you in the server log with "superfluous response.WriteHeader call", which is a sign of exactly this bug, often an error path that runs after something was already written.

You can watch this bug without starting a server. httptest.NewRecorder() is a fake ResponseWriter, and rec.Result() shows the response the client would have received:

package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

func broken(w http.ResponseWriter, r *http.Request) {
	w.Write([]byte("oops\n"))                     // first write sends 200 + headers
	w.WriteHeader(http.StatusInternalServerError) // too late: ignored
	w.Header().Set("X-Debug", "never sent")       // too late: headers are gone
}

func fixed(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("X-Debug", "sent")             // 1. headers
	w.WriteHeader(http.StatusInternalServerError) // 2. status
	w.Write([]byte("oops\n"))                     // 3. body
}

func call(name string, h http.HandlerFunc) {
	rec := httptest.NewRecorder()
	h(rec, httptest.NewRequest("GET", "/", nil))
	res := rec.Result() // the response as the client would see it
	fmt.Printf("%-7s status=%d X-Debug=%q body=%q\n",
		name, res.StatusCode, res.Header.Get("X-Debug"), strings.TrimSpace(rec.Body.String()))
}

func main() {
	call("broken", broken)
	call("fixed", fixed)
}
  1. We call call("broken", broken). It creates a fresh recorder and invokes the handler directly. A handler is just a function, so no network is needed.
  2. The very first Write has no status yet, so Go calls WriteHeader(200) for you. It also sniffs a Content-Type. The status line and headers are now committed; on a real server they are already on the wire.
  3. WriteHeader(500) comes too late and is ignored. A real server logs "superfluous response.WriteHeader call" here, which is the clue to look for in logs.
  4. Setting a header still changes the map in memory, but that map was already sent. The client never sees it.
  5. Result() returns the snapshot taken at commit time: an error page served with 200 OK. Monitoring would count this as a success.
  6. Now the fixed handler with a new recorder. Step 1: set headers while nothing is committed yet.
  7. Step 2: WriteHeader(500) commits the status together with the headers set so far.
  8. Step 3: the body. Write as much as you want from here on.
  9. Same bytes in the body, but now the client sees the right status and the header. Headers → status → body.

fixed   status=500 X-Debug="sent" body="oops"

Routing with ServeMux (Go 1.22+ patterns)

A mux (short for multiplexer, i.e. a router) looks at each request and picks the handler to run. Since Go 1.22 the standard http.ServeMux understands methods and path wildcards, so most APIs no longer need a third-party router. A pattern looks like:

[METHOD ][HOST]/[PATH]

GET /tasks/{id}          method + path with a wildcard
POST /tasks              only POST
/static/                 trailing slash: matches /static/ and everything below it
GET /files/{path...}     {name...} captures the rest of the path, slashes included
GET /{$}                 {$} means "exactly this path", so only "/"
api.example.com/         only requests whose Host is api.example.com

Inside the handler, r.PathValue("id") returns the text that matched {id}. It's always a string; parsing it into a number is your job.

package main

import (
	"fmt"
	"log"
	"net/http"
)

func show(label string) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "%-22s id=%q path=%q\n", label, r.PathValue("id"), r.PathValue("path"))
	}
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /tasks", show("list tasks"))
	mux.HandleFunc("POST /tasks", show("create task"))
	mux.HandleFunc("GET /tasks/{id}", show("get task"))
	mux.HandleFunc("DELETE /tasks/{id}", show("delete task"))
	mux.HandleFunc("GET /tasks/latest", show("latest (more specific)"))
	mux.HandleFunc("GET /files/{path...}", show("file (wildcard rest)"))
	mux.HandleFunc("GET /{$}", show("home (exact /)"))
	mux.HandleFunc("api.example.com/", show("host-specific"))

	log.Fatal(http.ListenAndServe(":8083", mux))
}

  1. GET /tasks: the method and the literal path match line 2 exactly. No wildcards, so both path values are empty.
  2. Same path, different method. The method is part of the pattern, so line 3 wins.
  3. /tasks/42 matches /tasks/{id}. A wildcard matches one whole path segment, so id = "42".
  4. /tasks/latest matches both line 4 and line 6. The rule: the most specific pattern wins. Line 6 matches only one path; line 4 matches many. So line 6 wins, and registration order doesn't matter.
  5. A {path...} wildcard must come last and swallows the remaining segments, slashes included.
  6. Without {$}, the pattern / would match every path as a catch-all. With it, only the root matches, and /about correctly returns 404.
  7. A PUT matches the path of lines 4-5 but no method. The mux answers 405 Method Not Allowed and fills in the Allow header for you. GET patterns also accept HEAD.
Gotcha: conflicting patterns panic at startup

If two patterns could match the same requests and neither is more specific (for example GET /tasks/{id} and GET /{kind}/latest), HandleFunc panics when you register them. That's a feature: you find routing ambiguity at startup, not in production. Also note that path matching is on the unescaped path, segment by segment, and the mux redirects /static to /static/ when only the slash version is registered.

Senior engineer tip

Always create your own mux with http.NewServeMux() and keep the route table in one function (we'll call it routes()). Being able to read every endpoint of a service in one screen is worth a lot during an incident. With 1.22 patterns, you only need a third-party router if you want things like route groups with per-group middleware, regex constraints, or automatic OpenAPI docs.

First, the storage. To keep examples runnable without a database, we use an in-memory store: a map protected by a sync.RWMutex. Many readers can hold the read lock at once; a writer gets exclusive access. Later in the chapter we'll write the same store against SQL.

package main

import (
	"errors"
	"slices"
	"sync"
	"time"
)

var ErrNotFound = errors.New("not found")

type Task struct {
	ID        int       `json:"id"`
	Title     string    `json:"title"`
	Done      bool      `json:"done"`
	CreatedAt time.Time `json:"created_at"`
}

// Store is an in-memory, concurrency-safe task store.
// Handlers run on many goroutines at once, so every access is locked.
type Store struct {
	mu     sync.RWMutex
	nextID int
	tasks  map[int]Task
	now    func() time.Time
}

func NewStore(now func() time.Time) *Store {
	return &Store{nextID: 1, tasks: map[int]Task{}, now: now}
}

func (s *Store) Create(title string) Task {
	s.mu.Lock()
	defer s.mu.Unlock()
	t := Task{ID: s.nextID, Title: title, CreatedAt: s.now()}
	s.tasks[t.ID] = t
	s.nextID++
	return t
}

func (s *Store) Get(id int) (Task, error) {
	s.mu.RLock()
	defer s.mu.RUnlock()
	t, ok := s.tasks[id]
	if !ok {
		return Task{}, ErrNotFound
	}
	return t, nil
}

func (s *Store) List() []Task {
	s.mu.RLock()
	defer s.mu.RUnlock()
	out := make([]Task, 0, len(s.tasks))
	for _, t := range s.tasks {
		out = append(out, t)
	}
	slices.SortFunc(out, func(a, b Task) int { return a.ID - b.ID })
	return out
}

func (s *Store) Update(id int, fn func(*Task)) (Task, error) {
	s.mu.Lock()
	defer s.mu.Unlock()
	t, ok := s.tasks[id]
	if !ok {
		return Task{}, ErrNotFound
	}
	fn(&t)
	s.tasks[id] = t
	return t, nil
}

func (s *Store) Delete(id int) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	if _, ok := s.tasks[id]; !ok {
		return ErrNotFound
	}
	delete(s.tasks, id)
	return nil
}

Notice the store returns ErrNotFound, its own error, not anything HTTP-specific. The storage layer shouldn't know about status codes; the handler translates errors into responses. That separation lets you swap the in-memory store for a SQL one without touching the error handling.

Response and request helpers

Every handler needs to send JSON and read JSON. Writing that code once, carefully, keeps handlers short and makes the API consistent: every error has the same shape, every body has a size limit.

package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"log/slog"
	"net/http"
	"strings"
)

// writeJSON sends v as JSON with the given status code.
func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	if err := json.NewEncoder(w).Encode(v); err != nil {
		// Too late to change the status code; just log it.
		slog.Error("encode response", "err", err)
	}
}

// apiError is the one error shape every endpoint returns.
type apiError struct {
	Error   string            `json:"error"`
	Details map[string]string `json:"details,omitempty"`
}

func writeError(w http.ResponseWriter, status int, msg string) {
	writeJSON(w, status, apiError{Error: msg})
}

const maxBody = 1 << 20 // 1 MiB

// readJSON decodes a single JSON object from the body into dst,
// with a size limit and strict field checking.
func readJSON(w http.ResponseWriter, r *http.Request, dst any) error {
	r.Body = http.MaxBytesReader(w, r.Body, maxBody)
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()

	if err := dec.Decode(dst); err != nil {
		var syntaxErr *json.SyntaxError
		var typeErr *json.UnmarshalTypeError
		var maxErr *http.MaxBytesError
		switch {
		case errors.As(err, &syntaxErr):
			return fmt.Errorf("malformed JSON at byte %d", syntaxErr.Offset)
		case errors.As(err, &typeErr):
			return fmt.Errorf("field %q must be %s", typeErr.Field, typeErr.Type)
		case errors.Is(err, io.ErrUnexpectedEOF):
			return errors.New("malformed JSON: unexpected end of body")
		case errors.Is(err, io.EOF):
			return errors.New("body must not be empty")
		case strings.HasPrefix(err.Error(), "json: unknown field "):
			return fmt.Errorf("unknown field %s", strings.TrimPrefix(err.Error(), "json: unknown field "))
		case errors.As(err, &maxErr):
			return fmt.Errorf("body must be at most %d bytes", maxErr.Limit)
		default:
			return err
		}
	}
	// Reject trailing data like `{"a":1}{"b":2}`.
	if dec.More() {
		return errors.New("body must contain a single JSON object")
	}
	return nil
}

Several defenses are packed in there:

  • http.MaxBytesReader caps the body at 1 MiB. Without it, a client can stream gigabytes at you and your decoder will happily buffer them. When the limit is hit, reads fail with *http.MaxBytesError and the server closes the connection.
  • DisallowUnknownFields rejects typos like "titel" instead of silently ignoring them.
  • dec.More() after decoding catches junk after the object.
  • Raw decoder errors ("invalid character 'h' looking for...") are turned into messages a client developer can act on.
func readJSON(w http.ResponseWriter, r *http.Request, dst any) error {
	r.Body = http.MaxBytesReader(w, r.Body, maxBody)
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	if err := dec.Decode(dst); err != nil {
		// ... translate err into a friendly message (see httpjson.go) ...
		return friendly(err)
	}
	if dec.More() {
		return errors.New("body must contain a single JSON object")
	}
	return nil
}
  1. The handler calls readJSON(w, r, &req). dst is a pointer to an empty createTaskRequest.
  2. We replace the body with a limited reader. From now on, reading byte 1,048,577 returns an error. The handler code doesn't change at all; it's still just an io.Reader.
  3. Create a streaming decoder over the body and switch on strict mode.
  4. Decode reads "title" into req.Title, then meets "priority", which has no matching field, and fails.
  5. The error is translated. The handler writes it with status 400. The real response was {"error":"unknown field \"priority\""}.
  6. For a different body with two objects, the first Decode succeeds, but More() sees another value waiting, so we reject it. A clean body reaches line 12 and returns nil.

Here is the size limit in action with a tiny 32-byte cap, so you can watch each of the three outcomes (created, too large, bad JSON):

package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

type input struct {
	Title string `json:"title"`
}

func create(w http.ResponseWriter, r *http.Request) {
	r.Body = http.MaxBytesReader(w, r.Body, 32) // cap the body at 32 bytes
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	var in input
	if err := dec.Decode(&in); err != nil {
		var mbe *http.MaxBytesError
		if errors.As(err, &mbe) {
			http.Error(w, fmt.Sprintf("body over %d bytes", mbe.Limit), http.StatusRequestEntityTooLarge)
			return
		}
		http.Error(w, "bad json: "+err.Error(), http.StatusBadRequest)
		return
	}
	w.WriteHeader(http.StatusCreated)
	fmt.Fprintf(w, "created %q\n", in.Title)
}

func main() {
	bodies := []string{
		`{"title":"ship it"}`,
		`{"title":"` + strings.Repeat("x", 40) + `"}`,
		`{"name":"x"}`,
	}
	for _, b := range bodies {
		rec := httptest.NewRecorder()
		create(rec, httptest.NewRequest("POST", "/tasks", strings.NewReader(b)))
		fmt.Printf("%d %s", rec.Code, rec.Body)
	}
}
  1. First body. We call the handler with a recorder. It wraps r.Body in a MaxBytesReader, which counts bytes as they are read and fails once more than 32 have been read.
  2. The decoder reads all 19 bytes, which is under the cap, and fills in. No error.
  3. Success path: status 201, then the body.
  4. Second body: 52 bytes. The decoder is still inside the title string when the reader hits 32 bytes and returns an error, which Decode passes back up.
  5. errors.As digs out the typed *http.MaxBytesError, so we can report the limit and use 413. On a real server, MaxBytesReader also tells the server to close the connection after the response.
  6. http.Error adds the trailing newline.
  7. Third body: small enough, but DisallowUnknownFields rejects a key that isn't in the struct. Without it, this request would "succeed" with an empty title.
  8. It isn't a size error, so errors.As fails and we fall through to a generic 400.
  9. In a real API you would translate this into a friendlier message, as readJSON does.
201 created "ship it"
413 body over 32 bytes
400 bad json: json: unknown field "name"

Handlers, validation and the full API

With the helpers in place, handlers become short and readable. Each one follows the same rhythm: parse input → validate → call the store → translate the result into a response.

package main

import (
	"errors"
	"net/http"
	"strconv"
	"strings"
	"time"
)

type API struct {
	store *Store
}

func (a *API) routes() *http.ServeMux {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", a.health)
	mux.HandleFunc("GET /tasks", a.listTasks)
	mux.HandleFunc("POST /tasks", a.createTask)
	mux.HandleFunc("GET /tasks/{id}", a.getTask)
	mux.HandleFunc("PATCH /tasks/{id}", a.updateTask)
	mux.HandleFunc("DELETE /tasks/{id}", a.deleteTask)
	mux.HandleFunc("GET /panic", func(http.ResponseWriter, *http.Request) {
		panic("something went very wrong") // to demo the recovery middleware
	})
	mux.HandleFunc("GET /slow", a.slow) // to demo graceful shutdown
	return mux
}

func (a *API) health(w http.ResponseWriter, r *http.Request) {
	writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
}

// slow simulates a 2-second job that respects cancellation.
func (a *API) slow(w http.ResponseWriter, r *http.Request) {
	select {
	case <-time.After(2 * time.Second):
		writeJSON(w, http.StatusOK, map[string]string{"result": "finished slow work"})

  • Validation is a method on the request type returning field → problem. Clients get all problems at once, not one per round trip.

Senior engineer tip

Decide your error format on day one and never deviate. A stable JSON shape (error + optional details, maybe a machine-readable code like "task_not_found") is what lets frontend and mobile teams write robust clients. Many teams adopt RFC 9457 "Problem Details" (application/problem+json) for this. And for 500s, log the real error with the request ID, but send the client only a generic message plus that ID.

A client sends PATCH /tasks/2 with body {"done":false}. In our handler, why do we need Done *bool instead of Done bool?
With a plain bool, both a missing field and an explicit false decode to false. With *bool, a missing field stays nil, so we only update fields the client actually sent. That's the essence of PATCH semantics.

Middleware: logging, recovery, request IDs, CORS

Some work should happen for every request: logging it, assigning an ID, catching panics, adding CORS headers, checking auth. Copy-pasting that into each handler would be awful. Middleware solves it: a function that takes a Handler and returns a new Handler that does something before and/or after calling the original.

type Middleware func(http.Handler) http.Handler

func example(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// before: runs on the way in
		next.ServeHTTP(w, r) // call the next layer
		// after: runs on the way out
	})
}

Before the full middleware file, here's one request traced end to end through a small onion: a logging middleware that captures the status code, then the mux, then the handler, and finally the response the client gets back:

package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

type statusRecorder struct {
	http.ResponseWriter
	status int
}

func (s *statusRecorder) WriteHeader(code int) {
	s.status = code
	s.ResponseWriter.WriteHeader(code)
}

func logging(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println("log: start", r.Method, r.URL.Path)
		sr := &statusRecorder{ResponseWriter: w, status: http.StatusOK}
		next.ServeHTTP(sr, r)
		fmt.Println("log: done ", sr.status)
	})
}

func getTask(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	fmt.Println("handler: id =", id)
	if id != "1" {
		http.Error(w, "not found", http.StatusNotFound)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	fmt.Fprintln(w, `{"id":1,"title":"write docs"}`)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /tasks/{id}", getTask)
	h := logging(mux)

	for _, path := range []string{"/tasks/1", "/tasks/7"} {
		rec := httptest.NewRecorder()
		h.ServeHTTP(rec, httptest.NewRequest("GET", path, nil))
		fmt.Printf("client: %d %s\n", rec.Code, strings.TrimSpace(rec.Body.String()))
	}
}
  1. The mux knows one route. logging(mux) wraps it, so h is the outermost layer, and every request enters there first.
  2. Request 1 enters h.ServeHTTP, which is the logging closure. Its "before" code runs.
  3. The middleware wraps the real writer in a statusRecorder. The default is 200, because a handler that never calls WriteHeader gets 200 implicitly.
  4. It passes sr (not w) to the mux. The mux matches the method and path, stores id=1 on the request, and calls getTask.
  5. r.PathValue("id") reads what the mux captured.
  6. The happy path writes a header and then the body. Fprintln calls sr.Write. statusRecorder doesn't override Write, so the embedded writer's Write runs and sends an implicit 200. sr.status is never touched, which is why the default of 200 was important.
  7. The handler returns, the mux returns, and we are back in the middleware's "after" code with the status in hand.
  8. The recorder holds the response as the client sees it.
  9. Request 2 follows the same path in: logging, then mux, then handler.
  10. http.Error calls w.WriteHeader(404). Because w is our sr, the overridden method runs: it records 404 and then forwards to the real writer.
  11. The early return unwinds back to the logger, which now logs 404. Without the wrapper, middleware has no way to read the status back from a ResponseWriter.

package main

import (
	"context"
	"crypto/rand"
	"fmt"
	"log/slog"
	"net/http"
	"runtime/debug"
	"time"

// Middleware wraps a Handler and returns a new Handler.
type Middleware func(http.Handler) http.Handler

// chain applies middlewares so the FIRST one listed is the OUTERMOST.
func chain(h http.Handler, mws ...Middleware) http.Handler {
	for i := len(mws) - 1; i >= 0; i-- {
		h = mws[i](h)
	}
	return h
}

type ctxKey struct{}

func requestIDFrom(ctx context.Context) string {
	id, _ := ctx.Value(ctxKey{}).(string)
	return id
}

// requestID reuses an incoming X-Request-ID or creates one.
func requestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" {
			id = rand.Text()[:12]
		}
		w.Header().Set("X-Request-ID", id)
		ctx := context.WithValue(r.Context(), ctxKey{}, id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

// statusRecorder remembers the status code the handler wrote.
type statusRecorder struct {
	http.ResponseWriter
	status int
	bytes  int
}

func (s *statusRecorder) WriteHeader(code int) {
	s.status = code
	s.ResponseWriter.WriteHeader(code)
}

func (s *statusRecorder) Write(b []byte) (int, error) {
	if s.status == 0 {
		s.status = http.StatusOK
	}
	n, err := s.ResponseWriter.Write(b)
	s.bytes += n
	return n, err
}

func (s *statusRecorder) Unwrap() http.ResponseWriter { return s.ResponseWriter }

func logging(log *slog.Logger) Middleware {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			start := time.Now()
			rec := &statusRecorder{ResponseWriter: w}
			next.ServeHTTP(rec, r)
			if rec.status == 0 {
				rec.status = http.StatusOK
			}
			log.Info("request",
				"id", requestIDFrom(r.Context()),
				"method", r.Method,
				"path", r.URL.Path,
				"status", rec.status,
				"bytes", rec.bytes,
				"dur", time.Since(start).Round(time.Microsecond),
			)
		})
	}
}

// recovery turns a panic in a handler into a 500 instead of a dropped connection.
func recovery(log *slog.Logger) Middleware {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			defer func() {
				if v := recover(); v != nil {
					if v == http.ErrAbortHandler { // deliberate abort: re-panic
						panic(v)
					}
					log.Error("panic",
						"id", requestIDFrom(r.Context()),
						"value", fmt.Sprint(v),
						"stack_bytes", len(debug.Stack()))
					w.Header().Set("Connection", "close")
					writeError(w, http.StatusInternalServerError, "internal server error")
				}
			}()
			next.ServeHTTP(w, r)
		})
	}
}

// cors allows browser apps from the given origin to call the API.
func cors(allowedOrigin string) Middleware {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			w.Header().Add("Vary", "Origin")
			if r.Header.Get("Origin") == allowedOrigin {
				w.Header().Set("Access-Control-Allow-Origin", allowedOrigin)
				w.Header().Set("Access-Control-Allow-Methods", "GET, POST, PATCH, DELETE")
				w.Header().Set("Access-Control-Allow-Headers", "Content-Type, X-Request-ID")
			}
			// Preflight: the browser asks permission before the real request.
			if r.Method == http.MethodOptions && r.Header.Get("Access-Control-Request-Method") != "" {
				w.WriteHeader(http.StatusNoContent)
				return
			}
			next.ServeHTTP(w, r)
		})
	}
}

A few design notes:

  • statusRecorder embeds the real ResponseWriter and overrides WriteHeader/Write to remember the status and byte count. The Unwrap method lets http.ResponseController reach the original writer for features like flushing.
  • Request IDs travel in the request's context.Context, under an unexported key type (ctxKey{}) so no other package can collide with it. If the caller already sent X-Request-ID (say, from a load balancer), we keep it so one ID follows the request across services.
  • recovery uses defer + recover(). Without it, net/http still recovers panics per connection, but it just logs a stack trace and drops the connection: the client gets no response at all. Ours logs with the request ID and returns a proper JSON 500.
  • CORS (Cross-Origin Resource Sharing) is how a browser decides whether JavaScript on localhost:5173 may call an API on localhost:8080. For non-simple requests the browser first sends an OPTIONS "preflight" asking permission; we answer it with 204 and the allowed methods and headers.

Gotcha: panics in other goroutines

recover() only catches panics in the same goroutine. If a handler starts go doWork() and that panics, your recovery middleware can't help and the whole process crashes. Any goroutine you start needs its own defer/recover, or better, use a library pattern like errgroup that handles it.

Here's the recovery idea in miniature. Watch the request ID travel through the context into the deferred recover, and the panic turn into a clean 500:

package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

type ctxKey struct{}

func requestID(next http.Handler) http.Handler {
	n := 0
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		n++
		id := fmt.Sprintf("req-%d", n)
		w.Header().Set("X-Request-ID", id)
		ctx := context.WithValue(r.Context(), ctxKey{}, id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func recovery(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if v := recover(); v != nil {
				id, _ := r.Context().Value(ctxKey{}).(string)
				fmt.Println("recovered:", v, "| id:", id)
				http.Error(w, "internal error", http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/ok", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "fine")
	})
	mux.HandleFunc("/boom", func(w http.ResponseWriter, r *http.Request) {
		var m map[string]int
		m["x"] = 1 // panics: assignment to entry in nil map
	})
	h := requestID(recovery(mux))

	for _, p := range []string{"/ok", "/boom"} {
		rec := httptest.NewRecorder()
		h.ServeHTTP(rec, httptest.NewRequest("GET", p, nil))
		fmt.Printf("client: %d id=%s body=%q\n", rec.Code, rec.Header().Get("X-Request-ID"), strings.TrimSpace(rec.Body.String()))
	}
}
  1. The onion is requestID outside, then recovery, then the mux. n lives in the requestID closure and is shared by every request. A real server would need an atomic here because requests run concurrently; this demo runs them one at a time.
  2. Request /ok: the outer layer creates an ID and sets the response header right away, so even an error response will carry it.
  3. WithValue makes a new context, and r.WithContext makes a shallow copy of the request carrying it. Every layer inside sees this new r.
  4. Recovery registers its deferred function and then calls the mux.
  5. The handler writes normally. When it returns, the deferred function runs, recover() returns nil, and nothing happens.
  6. The ID header made it to the client.
  7. Request /boom gets req-2 and goes through the same layers.
  8. Writing to a nil map panics. The goroutine starts unwinding the stack, running deferred calls as it goes. The handler and the mux have none.
  9. Recovery's deferred function runs, and recover() stops the panic and returns its value. The r it captured already carries the ID, so the log line can be correlated with the client's report.
  10. Nothing had been written yet, so we can still send a proper 500. If the handler had already written a body, this status would come too late.
  11. The client gets a clean error with the ID to quote in a bug report. The internal panic text is never leaked.
client: 200 id=req-1 body="fine"

client: 500 id=req-2 body="internal error"

http.Server: timeouts and why defaults are dangerous

http.ListenAndServe(addr, h) creates an http.Server with every timeout set to zero, which means no timeout at all. That lets a single client hold a connection open forever. The classic attack is Slowloris: open thousands of connections and send one header byte every few seconds. Each connection costs you a goroutine and a file descriptor, and eventually you run out. No exploit needed, just patience.

Always build the server yourself:

srv := &http.Server{
	Addr:              ":8080",
	Handler:           handler,
	ReadHeaderTimeout: 5 * time.Second,  // slowloris protection
	ReadTimeout:       10 * time.Second, // whole request, incl. body
	WriteTimeout:      15 * time.Second, // handler + writing response
	IdleTimeout:       60 * time.Second, // keep-alive connections
	MaxHeaderBytes:    1 << 20,
}

Every request carries a context. It is cancelled when the client disconnects or a deadline passes. A slow handler should watch r.Context().Done() and stop working for nobody:

package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"time"
)

func slow(w http.ResponseWriter, r *http.Request) {
	fmt.Println("handler: working...")
	select {
	case <-time.After(200 * time.Millisecond): // pretend to query a DB
		fmt.Fprintln(w, "report ready")
	case <-r.Context().Done(): // client went away or deadline hit
		fmt.Println("handler: stopping early:", r.Context().Err())
		return
	}
}

func main() {
	// Fast enough: a generous deadline.
	ctx, cancel := context.WithTimeout(context.Background(), time.Second)
	rec := httptest.NewRecorder()
	slow(rec, httptest.NewRequest("GET", "/report", nil).WithContext(ctx))
	cancel()
	fmt.Printf("client: %d %q\n", rec.Code, strings.TrimSpace(rec.Body.String()))

	// Too slow: the deadline fires first.
	ctx, cancel = context.WithTimeout(context.Background(), 50*time.Millisecond)
	defer cancel()
	rec = httptest.NewRecorder()
	slow(rec, httptest.NewRequest("GET", "/report", nil).WithContext(ctx))
	fmt.Printf("client: %d %q\n", rec.Code, strings.TrimSpace(rec.Body.String()))
}
  1. Request 1 gets a 1-second deadline. WithContext attaches it to the request, the same way the server attaches a context that is cancelled on client disconnect.
  2. The handler blocks in a select and waits for whichever channel is ready first.
  3. The 200ms "query" finishes well before the 1s deadline, so the first case wins and we write the body.
  4. Back in main, we call cancel() right away to release the context's timer. go vet warns if you forget.
  5. Request 2 has only 50ms. Same handler, same select.
  6. At 50ms the context's Done() channel closes, before the timer. We log and return. In a real app you would pass r.Context() to the DB call so the query itself is cancelled too.
  7. Gotcha: the handler returned without writing anything, so the status is the implicit 200 with an empty body. If the client is still listening (a deadline, not a disconnect), write a 503 or 504 before returning.
  8. The deferred cancel() fires when main returns. Calling it after the deadline already passed is harmless.

Graceful shutdown

When you deploy a new version, the old process is told to stop, usually with SIGTERM (Kubernetes, systemd, Docker) or SIGINT (Ctrl+C). If it just dies, every in-flight request fails: a user's payment, half an upload. Graceful shutdown means: stop accepting new connections, let the current requests finish, then exit.

Go gives you two tools:

  • signal.NotifyContext(ctx, signals...) returns a context that is cancelled when one of those signals arrives.
  • srv.Shutdown(ctx) closes the listeners, closes idle connections, then waits for active requests to finish, or until ctx expires. Meanwhile ListenAndServe returns http.ErrServerClosed immediately.
package main

import (
	"context"
	"errors"
	"log/slog"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	if err := run(); err != nil {
		slog.Error("fatal", "err", err)
		os.Exit(1)
	}
}

func run() error {
	log := slog.New(slog.NewTextHandler(os.Stderr, nil))

	// ctx is cancelled when we receive Ctrl+C (SIGINT) or SIGTERM (what Kubernetes sends).
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	api := &API{store: NewStore(time.Now)}
	handler := chain(api.routes(),
		requestID, // outermost: runs first, so every log line has an ID
		logging(log),
		recovery(log),
		cors("http://localhost:5173"),
	)

	srv := &http.Server{
		Addr:              ":8080",
		Handler:           handler,
		ReadHeaderTimeout: 5 * time.Second,  // slowloris protection
		ReadTimeout:       10 * time.Second, // whole request, incl. body
		WriteTimeout:      15 * time.Second, // handler + writing response
		IdleTimeout:       60 * time.Second, // keep-alive connections
		MaxHeaderBytes:    1 << 20,
	}

	// Start serving in a goroutine so main can wait for a signal.
	errCh := make(chan error, 1)
	go func() {
		log.Info("listening", "addr", srv.Addr)
		if err := srv.ListenAndServe(); !errors.Is(err, http.ErrServerClosed) {
			errCh <- err
		}
		close(errCh)
	}()

	select {
	case err := <-errCh:
		return err // failed to start, e.g. port already in use
	case <-ctx.Done():
		log.Info("shutdown signal received")
	}

	// Give in-flight requests up to 10s to finish.
	shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()
	if err := srv.Shutdown(shutdownCtx); err != nil {
		return err
	}
	log.Info("server stopped cleanly")
	return nil
}

  2. The server runs in its own goroutine. errCh is buffered (size 1) so the goroutine can always send without blocking, even if nobody reads.
  3. Main blocks on two events. If the port is taken, ListenAndServe fails right away and line 12 returns that error.
  4. A client is in the middle of GET /slow (a 2-second job) when we send SIGINT. The context is cancelled and we fall through the select.
  5. Shutdown closes the listening socket at once, so new connections are refused (our curl to /healthz got "connection refused"). ListenAndServe returns ErrServerClosed, which the goroutine ignores. Shutdown now waits for the one active request.
  6. The slow request completes normally with a 200. The client never noticed anything.
  7. With no active requests left, Shutdown returns nil, and we exit with status 0. Had the requests run past 10 seconds, Shutdown would return context.DeadlineExceeded.

Senior engineer tip: shutdown in Kubernetes

When a pod is deleted, Kubernetes sends SIGTERM and removes the pod from the Service endpoints at roughly the same time, so a few new requests can still arrive just after the signal. Many teams first fail the readiness probe and sleep a few seconds before calling Shutdown. Make sure your shutdown timeout is shorter than terminationGracePeriodSeconds (30s by default). And don't make the signal context the server's BaseContext: that would cancel every in-flight request's context the moment the signal arrives, which is the opposite of graceful.

After srv.Shutdown(ctx) is called, what does the still-running srv.ListenAndServe() return?
ListenAndServe returns ErrServerClosed as soon as the listener is closed. Shutdown itself is what blocks until active requests are done. That's why the program must wait for Shutdown to return before exiting, not for ListenAndServe.

http.Client: calling other services

Services also call other services. The same warning applies: http.Get and http.DefaultClient have no timeout. If the other side hangs, your goroutine hangs forever, and under load you'll pile up thousands of them. Always create a client with a Timeout, and pass a context so the caller's deadline or cancellation flows through.

package main

import (
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

type Task struct {
	ID    int    `json:"id"`
	Title string `json:"title"`
}

// fetchTask is how a well-behaved client call looks.
func fetchTask(ctx context.Context, c *http.Client, url string) (Task, error) {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
	if err != nil {
		return Task{}, err
	}
	req.Header.Set("Accept", "application/json")

	resp, err := c.Do(req)
	if err != nil {
		return Task{}, fmt.Errorf("request failed: %w", err)
	}
	defer resp.Body.Close() // ALWAYS close the body, or the connection leaks

	if resp.StatusCode != http.StatusOK {
		// Read a little of the body for the error message, then give up.
		msg, _ := io.ReadAll(io.LimitReader(resp.Body, 512))
		return Task{}, fmt.Errorf("unexpected status %d: %s", resp.StatusCode, msg)
	}
	var t Task
	if err := json.NewDecoder(io.LimitReader(resp.Body, 1<<20)).Decode(&t); err != nil {
		return Task{}, fmt.Errorf("decoding: %w", err)
	}
	return t, nil
}

func main() {
	// httptest.NewServer starts a real server on a random local port.
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		switch r.URL.Path {
		case "/tasks/1":
			w.Write([]byte(`{"id":1,"title":"from the server"}`))
		case "/slow":
			time.Sleep(300 * time.Millisecond)
			w.Write([]byte(`{"id":2}`))
		default:
			http.Error(w, `{"error":"task not found"}`, http.StatusNotFound)
		}
	}))
	defer srv.Close()

	// Never use http.DefaultClient in production: it has NO timeout.
	client := &http.Client{Timeout: 2 * time.Second}

	t, err := fetchTask(context.Background(), client, srv.URL+"/tasks/1")
	fmt.Printf("ok:       %+v err=%v\n", t, err)

	_, err = fetchTask(context.Background(), client, srv.URL+"/tasks/9")
	fmt.Println("404:     ", err)

	// A per-call deadline via context, shorter than the client timeout.
	ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
	defer cancel()
	_, err = fetchTask(ctx, client, srv.URL+"/slow")
	fmt.Println("ctx:     ", err)
	fmt.Println("is DeadlineExceeded:", errors.Is(err, context.DeadlineExceeded))

	// Client.Timeout covers the whole exchange, including reading the body.
	short := &http.Client{Timeout: 50 * time.Millisecond}
	_, err = fetchTask(context.Background(), short, srv.URL+"/slow")
	fmt.Println("timeout: ", err)
}

Rules for every client call:

  • Close the body with defer resp.Body.Close(), even on non-200 responses. An unclosed body keeps the TCP connection busy and it can't be reused.
  • Check the status code. A 404 or 500 is not an error from Do: err is only for network-level failures.
  • Limit what you read, just like on the server.
  • Reuse one client. http.Client is safe for concurrent use and holds a connection pool. Creating one per request throws the pool away.
Senior engineer tip

For high-traffic service-to-service calls, tune the http.Transport: MaxIdleConnsPerHost defaults to only 2, which causes constant reconnects when you make many parallel calls to one host. Set it to match your concurrency. Add retries only for idempotent requests (GET, PUT, DELETE), with exponential backoff and jitter, and always under an overall deadline.

database/sql: talking to a real database

Most APIs store data in a SQL database. Go's database/sql package is a generic interface; a driver package teaches it a specific database (PostgreSQL via pgx, MySQL, SQLite...). You import the driver for its side effect of registering itself, then only use database/sql types in your code.

The most important fact: *sql.DB is not a connection, it's a connection pool. Create it once at startup, share it everywhere (it's safe for concurrent use), and close it at shutdown. Each query borrows a connection and gives it back when done.

Here's our task store written against SQL. It needs a driver and a database to actually run, but it was compiled and checked with go vet:

package main

import (
	"context"
	"database/sql"
	"errors"
	"fmt"
	"time"
	// The driver registers itself in an init function. Pick one, e.g.:
	// _ "github.com/jackc/pgx/v5/stdlib"   // PostgreSQL, driver name "pgx"
	// _ "modernc.org/sqlite"               // SQLite (pure Go), driver name "sqlite"
)

var ErrNotFound = errors.New("not found")

type Task struct {
	ID        int64
	Title     string
	Done      bool
	CreatedAt time.Time
}

type SQLStore struct {
	db *sql.DB
}

// Open creates the pool and checks that the database is reachable.
func Open(ctx context.Context, driver, dsn string) (*SQLStore, error) {
	db, err := sql.Open(driver, dsn) // does NOT connect yet
	if err != nil {
		return nil, err
	}
	// Pool tuning: *sql.DB is a pool of connections, safe for concurrent use.
	db.SetMaxOpenConns(25)                  // hard cap on connections to the DB
	db.SetMaxIdleConns(25)                  // keep them warm between requests
	db.SetConnMaxLifetime(30 * time.Minute) // recycle (load balancers, failover)
	db.SetConnMaxIdleTime(5 * time.Minute)

	ctx, cancel := context.WithTimeout(ctx, 5*time.Second)
	defer cancel()
	if err := db.PingContext(ctx); err != nil { // the first real connection
		db.Close()
		return nil, fmt.Errorf("ping: %w", err)
	}
	return &SQLStore{db: db}, nil
}

func (s *SQLStore) Close() error { return s.db.Close() }

// Get reads one row. Placeholders ($1) keep user input out of the SQL text.
func (s *SQLStore) Get(ctx context.Context, id int64) (Task, error) {
	var t Task
	err := s.db.QueryRowContext(ctx,
		`SELECT id, title, done, created_at FROM tasks WHERE id = $1`, id,
	).Scan(&t.ID, &t.Title, &t.Done, &t.CreatedAt)
	if errors.Is(err, sql.ErrNoRows) {
		return Task{}, ErrNotFound // translate to the app's own error
	}
	if err != nil {
		return Task{}, fmt.Errorf("get task %d: %w", id, err)
	}
	return t, nil
}

// List reads many rows. Note the three things you must always do.
func (s *SQLStore) List(ctx context.Context, limit int) ([]Task, error) {
	rows, err := s.db.QueryContext(ctx,
		`SELECT id, title, done, created_at FROM tasks ORDER BY id LIMIT $1`, limit)
	if err != nil {
		return nil, err
	}
	defer rows.Close() // 1. close, or the connection never returns to the pool

	var out []Task
	for rows.Next() {
		var t Task
		if err := rows.Scan(&t.ID, &t.Title, &t.Done, &t.CreatedAt); err != nil {
			return nil, err // 2. check Scan errors
		}
		out = append(out, t)
	}
	return out, rows.Err() // 3. check the error that ended the loop
}

// Create inserts a row and returns it (RETURNING is PostgreSQL/SQLite syntax).
func (s *SQLStore) Create(ctx context.Context, title string) (Task, error) {
	t := Task{Title: title}
	err := s.db.QueryRowContext(ctx,
		`INSERT INTO tasks (title) VALUES ($1) RETURNING id, done, created_at`, title,
	).Scan(&t.ID, &t.Done, &t.CreatedAt)
	return t, err
}

// Complete marks a task done; ExecContext is for statements without rows.
func (s *SQLStore) Complete(ctx context.Context, id int64) error {
	res, err := s.db.ExecContext(ctx, `UPDATE tasks SET done = true WHERE id = $1`, id)
	if err != nil {
		return err
	}
	n, err := res.RowsAffected()
	if err != nil {
		return err
	}
	if n == 0 {
		return ErrNotFound
	}
	return nil
}

// MoveTasks shows a transaction: all statements succeed together or not at all.
func (s *SQLStore) MoveTasks(ctx context.Context, fromUser, toUser int64) (err error) {
	tx, err := s.db.BeginTx(ctx, nil)
	if err != nil {
		return err
	}
	// Rollback is a no-op after a successful Commit, so always defer it.
	defer tx.Rollback()

	if _, err := tx.ExecContext(ctx,
		`UPDATE tasks SET owner_id = $1 WHERE owner_id = $2`, toUser, fromUser); err != nil {
		return fmt.Errorf("move: %w", err)
	}
	if _, err := tx.ExecContext(ctx,
		`INSERT INTO audit (action, from_user, to_user) VALUES ('move', $1, $2)`, fromUser, toUser); err != nil {
		return fmt.Errorf("audit: %w", err)
	}
	return tx.Commit()
}

// BulkInsert shows a prepared statement: parsed once, executed many times.
func (s *SQLStore) BulkInsert(ctx context.Context, titles []string) error {
	tx, err := s.db.BeginTx(ctx, nil)
	if err != nil {
		return err
	}
	defer tx.Rollback()

	stmt, err := tx.PrepareContext(ctx, `INSERT INTO tasks (title) VALUES ($1)`)
	if err != nil {
		return err
	}
	defer stmt.Close()

	for _, title := range titles {
		if _, err := stmt.ExecContext(ctx, title); err != nil {
			return fmt.Errorf("insert %q: %w", title, err)
		}
	}
	return tx.Commit()
}

Danger: SQL injection

Never build SQL with string formatting: fmt.Sprintf("SELECT ... WHERE title = '%s'", title). A title of '; DROP TABLE tasks; -- becomes part of your SQL. Always use placeholders ($1 for PostgreSQL, ? for MySQL/SQLite) and pass values as arguments. The driver sends them separately from the SQL text, so they can never be executed as code.

Gotchas

NULL columns can't be scanned into a plain string; use sql.NullString, sql.Null[T] (Go 1.22+) or a pointer. Leaked rows: returning early from a rows.Next() loop without rows.Close() keeps a connection checked out; leak enough and every query blocks waiting for the pool. Inside a transaction, using s.db instead of tx runs that query on a different connection, outside the transaction.

Senior engineer tip

Always use the ...Context variants and pass r.Context() from the handler. When a client disconnects or a deadline passes, the driver cancels the query on the database side too, instead of letting an expensive query run for nobody. Set SetMaxOpenConns deliberately: total connections = instances × max open, and that has to fit under your database's connection limit. Libraries like sqlc (generate type-safe Go from SQL) or sqlx remove most of the Scan boilerplate while staying close to plain SQL.

Exercise 1: add pagination to GET /tasks

Support GET /tasks?limit=10&offset=20. Default limit 20, maximum 100. Reject negative or non-numeric values with a 400 and our usual error shape. Hint: read with r.URL.Query().Get, parse with strconv.Atoi, and slice the sorted list with bounds checks (min is your friend).

Solution
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strconv"
)

func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	json.NewEncoder(w).Encode(v)
}

// intParam reads a non-negative integer query parameter with a default.
func intParam(r *http.Request, name string, def int) (int, error) {
	s := r.URL.Query().Get(name)
	if s == "" {
		return def, nil
	}
	n, err := strconv.Atoi(s)
	if err != nil || n < 0 {
		return 0, fmt.Errorf("%s must be a non-negative integer", name)
	}
	return n, nil
}

func listTasks(all []int) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		limit, err := intParam(r, "limit", 20)
		if err != nil {
			writeJSON(w, http.StatusBadRequest, map[string]string{"error": err.Error()})
			return
		}
		offset, err := intParam(r, "offset", 0)
		if err != nil {
			writeJSON(w, http.StatusBadRequest, map[string]string{"error": err.Error()})
			return
		}
		limit = min(limit, 100)
		start := min(offset, len(all))
		end := min(start+limit, len(all))
		writeJSON(w, http.StatusOK, map[string]any{
			"items": all[start:end], "offset": offset, "limit": limit, "total": len(all),
		})
	}
}

func main() {
	ids := make([]int, 25)
	for i := range ids {
		ids[i] = i + 1
	}
	mux := http.NewServeMux()
	mux.HandleFunc("GET /tasks", listTasks(ids))

	for _, url := range []string{"/tasks?limit=5", "/tasks?limit=5&offset=22", "/tasks?offset=100", "/tasks?limit=-1"} {
		rec := httptest.NewRecorder()
		mux.ServeHTTP(rec, httptest.NewRequest("GET", url, nil))
		fmt.Printf("GET %-26s %d %s", url, rec.Code, rec.Body)
	}
}
  1. listTasks(ids) returns a closure that captures the 25 IDs, and the mux routes GET /tasks to it.
  2. Request 1 goes into the mux, which ignores the query string when matching and calls our handler.
  3. In intParam, Query().Get("limit") returns "5", which parses fine and isn't negative.
  4. There is no offset in the URL, so Get returns "" and we use the default 0.
  5. Clamp everything with min: limit to 100, start to the length, end to the length. These clamps mean slicing can never panic.
  6. writeJSON sets the header, sends 200, and encodes. The keys come out sorted because it's a map.
  7. Request 2: the last page. start+limit would be 27, past the end, and min trims it to 25, so only 3 items come back.
  8. Request 3: offset beyond the end. start clamps to 25, so we get the empty slice all[25:25]. It is empty but not nil, so it encodes as [], not null. Clients will thank you.
  9. Request 4: Atoi("-1") succeeds, but n < 0 fails our rule. The handler writes 400 and returns, so the success code below never runs.

Exercise 2: an API-key auth middleware

Write func requireKey(key string) Middleware that rejects requests without the header Authorization: Bearer <key> with a 401 JSON error, except for GET /healthz. Compare keys with crypto/subtle.ConstantTimeCompare so an attacker can't guess the key from response timing. Test it with httptest.

Solution
package auth

import (
	"crypto/subtle"
	"encoding/json"
	"net/http"
	"strings"
)

type Middleware func(http.Handler) http.Handler

func requireKey(key string) Middleware {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			if r.Method == http.MethodGet && r.URL.Path == "/healthz" {
				next.ServeHTTP(w, r) // public endpoint
				return
			}
			got, ok := strings.CutPrefix(r.Header.Get("Authorization"), "Bearer ")
			if !ok || subtle.ConstantTimeCompare([]byte(got), []byte(key)) != 1 {
				w.Header().Set("Content-Type", "application/json")
				w.Header().Set("WWW-Authenticate", "Bearer")
				w.WriteHeader(http.StatusUnauthorized)
				json.NewEncoder(w).Encode(map[string]string{"error": "missing or invalid API key"})
				return
			}
			next.ServeHTTP(w, r)
		})
	}
}

Key takeaways

  • Everything is a Handler: ServeHTTP(w, r). HandlerFunc adapts plain functions; routers and middleware are Handlers too.
  • Write responses in order: headers → status → body. Each request runs in its own goroutine, so protect shared state.
  • Go 1.22 ServeMux patterns (GET /tasks/{id}, {path...}, {$}) plus r.PathValue cover most routing; the most specific pattern wins and 405s are automatic.
  • Centralize JSON: MaxBytesReader, DisallowUnknownFields, friendly errors, one error shape, deliberate status codes, validation that reports all problems.
  • Middleware is func(http.Handler) http.Handler; the first in the chain is the outermost. Use it for request IDs, logging, recovery and CORS.
  • Never ship the zero-timeout defaults: set ReadHeaderTimeout, ReadTimeout, WriteTimeout, IdleTimeout on the server and Timeout on every client.
  • Graceful shutdown = signal.NotifyContext + srv.Shutdown(ctxWithTimeout); wait for Shutdown, not ListenAndServe.
  • On the client side: reuse one client, pass contexts, close bodies, check status codes.
  • *sql.DB is a pool: open once, use ...Context methods with placeholders, handle sql.ErrNoRows, always close rows, and use defer tx.Rollback() + Commit() for transactions.
